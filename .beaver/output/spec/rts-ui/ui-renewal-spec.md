# UI 개선 명세

## Feature Description
사용자는 전체 UI의 완성도를 개선하고 싶으며, 특히 증강·캐릭터 상세정보·증강 뽑기·증강 도감을 지목했다. 현재 승인된 분위기는 **새하얀 반투명 물결과 은은한 연보라 선택 표시**다. 이전 크림·브라운 방향을 대체한다.

이번 작업은 기존 게임의 UI 개선이다. 새 게임 GDD를 만들지 않고 기존 Phase 11 안에서 진행한다. 사용자 승인 후 실제 코드와 Maker Play에 적용했다. 검증 기록은 같은 주제의 report 문서를 따른다.

## 진입점
- Method: 기존 클라이언트 팝업 열기·탭 전환·행 선택·HUD 버튼.
- Path: `RtsPopupLogic.Open("augment" / "pick" / "codex")`, `RtsUnitPopupLogic.OpenUnit`, `RtsAugmentLogic.BuyFromHud`.
- Request: 기존 증강·유닛 식별자 및 선택 상태.
- Response: 동일한 기능을 새로운 배치와 일관된 시각 상태로 표시한다.

## 확인된 개선 근거
| 화면 | 코드에서 확인한 현재 구성 | 개선 방향 |
|---|---|---|
| 증강 | 효과 설명 높이 170px와 대상 시작 위치가 고정. 36px 대상 칩에 번호·직업·레벨을 표시 (`RtsPopupLogic.mlua:2004`) | 효과 → 대상 → 적용의 순서. 짧은 효과 아래 빈 공간을 줄이고 대상 버튼을 넓힌다 |
| 캐릭터 상세 | 능력치 14~15px, 증강 증가량 13px. 액티브 설정이 설명 폭에서 236px를 차지 (`RtsUnitPopupLogic.mlua:226,463`) | 캐릭터·능력치와 스킬 영역 구분. 잠금 설정은 설명 아래에 배치해 본문 폭을 확보 |
| 뽑기 HUD | 280×44px 버튼 안에 이름·가격·프리즘 남은 수·확률을 한 줄로 표시 (`RtsHudLogic.mlua:543,671`) | 주 행동과 가격을 첫 줄, 프리즘 정보를 둘째 줄에 배치 |
| 3택1 | 340×360px 카드에 설명 15px, 지속 발광과 둘레 효과 (`RtsPopupLogic.mlua:2316,2400`) | 이름·효과·받기 순서를 세 카드에서 맞춘다. 연출은 등장 시 중심, 본문 영역은 안정적으로 유지 |
| 도감 | 일반 등급은 56px 한 행에 이름·효과·확률. 프리즘은 별도 펼치기 (`RtsPopupLogic.mlua:2235`) | 이름과 확률은 머리줄, 효과는 다음 줄. 프리즘 펼치기는 유지하며 설명 높이를 내용에 맞춘다 |

## Business Rules
- 가격·확률·천장·지급·중복·적용 조건 및 서버 검증은 기존 값을 사용한다. 문구 안에 수치를 복제하지 않는다.
- 추가 사용자 위임에 따라 HUD는 증강 통합 버튼 하나로 바꾼다. 구매는 창의 뽑기 탭에서 실행한다. 3택1 수령 후 증강 창에서 대상을 지정하는 흐름과 팬텀 해금 예외를 유지한다.
- 증강 미지정 우선 정렬과 숨기기 기본값을 유지한다. 보유 등급 탭은 제거하고 모든 등급을 함께 표시한다.
- 등급 문양 안에 능력치 아이콘을 합성하고 직업 프리즘11종은 대응 공식 스킬 아이콘을 사용한다. 썬콜은 승인된 흉상을 쓰고 다른 직업은 기존 외형을 쓴다.
- Tab·Space·ESC·접기, 영구 잠금, 메소 부족, 최대 레벨, 관전 상태의 기존 의미를 보존한다.
- 부분 갱신과 선택·스크롤 상태를 보존한다. 탭 전환 시 창 전체를 다시 열지 않는다.
- 게임 반영과 시각 검증 전에는 구현 완료로 표시하지 않는다. 커밋·푸시는 별도 사용자 지시를 따른다.

## Decisions
- 확정: 백색 물결 시안 승인 및 프리즘 스킬 그림 합성 요청.
- 확정: 기존 UI 전체가 개선 대상이며, 사용자가 지목한 네 영역을 먼저 다룬다.
- 작업 기준: `docs/design-system.md`의 색상 역할·1920×1080 기준을 재사용한다. 백색은 읽는 면, 짙은 회색은 본문, 연보라는 선택 강조다. 등급은 합성 문양과 좁은 띠로 표시한다.
- 시각 배치의 사용자 확인은 첫 시안에서 받는다. 아래 계획의 치수는 구현 목표이며 승인된 완성 화면으로 취급하지 않는다.

- 규칙: `docs/ui-screens.md`, `docs/design-system.md`, `docs/design-handoff.md`, `.beaver/memory/workflow.md`.
