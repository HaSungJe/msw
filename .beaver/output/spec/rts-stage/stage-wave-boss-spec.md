## Feature Description

로드맵 **Phase 6(스테이지·몬스터 웨이브, #22~#26) + Phase 7(보스·클리어·결과, #27~#30)** 을 한 번에 만든다(2026-09-23 사용자 "이번 라운드에서 보스까지 다 만들자. 굳이 나눌 필요가 없음").

지금은 개발모드 시험대(무적 주니어 발록 1기 · Lv50 무료 영입 · 메소 100만)로 전투만 확인할 수 있다. 이번 작업으로 **실제 한 판**이 돈다:

1. 첫 유저가 들어오고 **5초 뒤 1스테이지 시작**. 이후 `.info/monster-wave.md`의 132 스테이지를 순서대로, **방 전체가 같은 시계로** 진행한다.
2. 몬스터 스테이지(20초)마다 살아 있는 구역에 **초당 2마리 × 20초 = 40마리**가 S에서 나와 트랙을 돈다. 잡으면 사망 연출·사망음 뒤 사라지고 **메소가 그 구역 주인에게 100%** 들어온다.
3. 구역 **필드에 살아 있는 몹이 110마리**가 되면 그 유저는 탈락 — 유닛 전멸, 비석, 결과 팝업(나가기 / 닫고 관전).
4. 보스 스테이지(60초)에는 필드의 일반 몹을 **보관(숨기고 멈춤)** 하고, 보스가 S에서 출발해 **60초에 트랙 한 바퀴** 속도로 E를 향해 걷는다. 모든 유닛 사거리는 10으로 고정. E에 닿기 전에 못 잡으면 탈락. 보스전이 끝나면 보관한 몹이 제자리에서 다시 돈다.
5. 검은 마법사 4페이즈를 잡으면 **클리어**. 탈락·클리어 모두 결과 팝업(도달 스테이지 · 처치 수 · 결과 · 보스 HP% · 개인 최고) + **나가기**. 개인 최고 기록은 서버(UserDataStorage)에 저장 — 전광판 등록은 Phase 8 #42.
6. 영입은 **항상 Lv1**, **5라운드마다 1명씩 칸이 열린다**(1·5·10·15·20·25라운드 → 자쿰 전 6명, 메소 안 씀). 영입 버튼은 우측 패널에서 빼서 **화면 상단 가운데에 크게**, 첫 영입은 판 시작과 함께 영입 창이 열린다. 레벨업은 **드랍 메소로**(한 판 총 768,000 = 6기 전원 50레벨). 시험대(주니어 발록·100만 메소·Lv50 영입·시연 유닛·시연 순회 몹)는 전부 없앤다. 테스트 프리즘 버튼만 증강 시스템(Phase 4) 전까지 남긴다.

## 진입점 (Entry Point)

- Method: 서버 Logic 메서드 + 서버→클라 Client 메서드(마지막 인자 userId) + 클라 팝업 버튼 → 서버 요청
- Path:
  - `RtsBootstrapLogic.HandleUserEnterEvent` → `RtsStageLogic.OnUserEnter(userId)` — 첫 입장이면 5초 카운트다운 후 `StartRun`, 진행 중이면 합류
  - `RtsStageLogic.BeginStage(n)` / `EndStage()` — 스테이지 전환(방 전역). 종류별로 `RtsWaveLogic`(몬스터) · `RtsBossLogic`(보스) · 아무것도(쉬는) 호출. 전환 훅 자리: 증강 지급(Phase 4)·BGM(Phase 10)
  - `RtsWaveLogic.SpawnTick()` — 0.5초마다 살아 있는 구역에 1마리씩(스테이지당 40)
  - `RtsMonsterComponent.Die(killerUserId)` — HP 0 → 드랍·처치 수·사망 연출
  - `RtsBossLogic.OnBossReachedEnd(zone)` / `OnBossKilled(zone)`
  - `RtsRunResultLogic.Eliminate(userId, reason)` / `Clear(userId)` / `ShowResult(…, userId)` / `RequestExit()`
- Request: 유저 입력은 결과 팝업의 **나가기**(서버 `RequestExit`, senderUserId 검증)와 **닫기**(클라 전용)뿐. 나머지는 전부 서버 타이머 구동
- Response: HUD 갱신(시간 칩 = 스테이지 번호·맵 이름·남은 시간 / 필드 칩 = n/110 / 메소 칩), 플레이어 목록 생존 표시, 결과 팝업

## Business Rules

### 스테이지 진행 (방 전역, #23)
- 132 스테이지 = 몬스터 113 + 몹 풀 참조 [73] 1 + 쉬는 [115] 1 + 보스 17(아이온·얄다바오트는 한 스테이지에 2체). 순서·이름·배경음은 `.info/monster-wave.md` 그대로.
- 길이: 몬스터 **20초** / 보스 **60초** / 쉬는 **30초**(2026-09-23 사용자). 스테이지 사이 대기 없음.
- 시작: **첫 유저 입장 5초 뒤 자동 시작**(2026-09-23 사용자 "게임이 접속되면 바로 시작" — 방 기능이 생겨도 같은 규칙). 5초 동안 시간 칩에 "시작까지 n".
- 진행 중 들어온 유저는 구역을 받고 **다음 스테이지부터** 스폰이 붙는다(지금 스테이지는 빈 채로). 판이 끝난 뒤 들어오면 맵을 초기화하고 새 판(5초 뒤).
- 스테이지 번호는 **1~132 순번**(점수·HUD용). `.info`의 태그([n] / [보스])는 표에 같이 둔다 — 증강 지급표(augmentation.md)가 태그 번호를 쓴다.
- 보스 스테이지는 **살아 있는 모든 유저가 보스를 잡으면 3초 뒤 조기 종료**(아무도 할 일이 없는 60초 대기를 줄임). 한 명이라도 싸우는 중이면 60초 끝까지.
- 판 종료: 모든 유저가 탈락 또는 클리어. 끝나면 스폰·타이머 정지.

### 스테이지·몬스터 표 (#22)
- `RtsStageTableLogic`(신규)이 132 스테이지와 몬스터 247종(일반 229 + 보스 18)을 가진다. 스테이지 행: 순번·태그·맵 이름·종류·지역·배경음 키·몹 id 목록·**스테이지 체력**·**스테이지 메소 총액**. 몬스터 행: 이름·이동 클립·사망 클립·사망음·스케일·피격 박스·사망 클립 길이.
- 표는 **생성물** — `tools/gen-stage-table.py`가 로컬 `.info/monster-wave.md`·`monster.md`·`level.md`·`balance-detail.md`를 읽어 표 부분을 다시 쓴다. 손으로 고치지 않는다(수치 하드코딩 금지 규칙).
- **[73] 무토가 잠긴 곳** = [59]~[65]의 몹 8종(슬픔·즐거움·암석·화염·강인한 영혼·안식의 에르다스, 아르마, 아르마의 부하)을 균등하게.
- 한 스테이지 40마리는 목록의 몹 종류를 **고르게 나눠 섞은 순서**로(3종이면 14·13·13).
- 이동속도는 전부 100(초당 3.5유닛). 물리/마법 방어율은 0(상성 없음 — 로드맵 Non-Goals).

### 몬스터 자산 매칭 (#22)
- 몬스터마다 자산 3개(이동·사망 클립 + 사망음, 로드맵 규칙). 공식 자산을 **이름으로 검색**하면 원작 경로가 나온다(2026-09-23 실측: "파란 달팽이" → `mob/0100101/move`·`die1`, `sound/mob/0100101/die`). 이 경로로 몹 번호를 확정하고 같은 번호의 `move`(없으면 `stand`)·`die1`·`sound/.../die`를 잡는다.
- 크기는 원작 픽셀 차이가 커서(달팽이 ≈ 40px, 타우로마시스 ≈ 150px) 이동 클립 첫 프레임 크기로 **몬스터마다 스케일**을 정한다 — 일반 몹은 화면에서 비슷한 덩치(달팽이 스케일 2.5 기준 ≈ 높이 1.0~1.6유닛 안), 보스는 더 크게(≈ 3유닛). 피격 박스·체력바 위치도 그 크기로.
- 매칭 결과는 `.info/monster.md` 칸(기본·사망 애니메이션, 사망 보이스)에 채우고, 몬스터별 썸네일 시트로 확인받는다. **보스 18종은 프리즘 때처럼 사용자가 시트를 보고 바꿀 수 있다**(자쿰 팔·혼테일 머리처럼 여러 부위인 보스는 대표 클립 1개로 시작).

### 경제 — 오름세 수입 + 스페셜 스테이지 + 레벨업 비용 재조정 (#25, 2026-09-23 사용자 5차)
- 사용자: "메소는 계속 오름세, 아케인리버 기준으로 확 늘어나게" · "일반 스테이지를 스페셜 스테이지와 일반 스테이지로 — 스페셜은 메소 2배" · "메소 단위는 10원" · "레벨업 메소 자체를 조정".
- **수입**: 한 판 768,000(듄켈 직전 6기 전원 50). 기본 곡선 = 몬스터 라운드 체력^0.101 비례 오름세 × 아케인리버(65)부터 ×1.67. **스페셜 스테이지 = 보스 바로 앞 몬스터 라운드 13개**(9·25·28·42·46·55·59·63·88·109·113·120·126) — 메소 ×2, 시간 칩에 '스페셜' 표시. 마리당 10메소 단위(1라운드 60 → 엘나스 90 → 리프레 100 → 세계수 110 → 아케인 200 → 리멘 220, 스페셜은 2배). 듄켈 뒤는 0.
- **보스 직전 목표 레벨대**(레벨은 레벨대): 자쿰 30대×2+20대×4 / 혼테일 40대+30대×2+20대×3(사용자 '20대 2개' — 6명이라 3개로) / 핑크빈 40대×2+30대×4 / 시그너스 50+40대+30대×4 / 루시드 50×3+40대×3 / 진 힐라 50×5+40대 / 듄켈 50×6.
- **레벨업 비용표(교체)**: 표준 빌드(번 메소를 다 씀 — 이번 보스 레벨대 입구 → 다음 보스 준비(지금 레벨대 끝까지만) → 남으면 레벨대 끝까지, 늘 가장 낮은 유닛부터)가 7곳 모두 목표 레벨대에 들어오고 보스 직전 남는 메소 ≤ 10%가 되게 맞춘 값. 레벨당 2~9 = 70 · 10 벽 440 / 11~19 = 350 · 20 벽 1,140 / 21~29 = 470 · 30 벽 1,420 / 31~39 = 630 · 40 벽 1,710 / 41~49 = 6,900 · 50 벽 47,580 → 누적 10레벨 1,000 · 20 5,290 · 30 10,940 · 40 18,320 · 50 128,000. 41레벨부터 크게 뛰어 50레벨 6기가 한 판 메소의 대부분을 쓴다.
- 원본: `.info/level.md`(수입·비용표 교체), 라운드별 값 = `.info/monster.md` 끝 표. 방출 환급 30%도 10메소 단위로 내림.

### 체력 — 보스는 최적 조합 고점의 %, 일반은 테마 계단 + 라인 클리어 한계 (#22, 2026-09-23 사용자 5차)
- **보스**(사용자 5·6차 — "레벨대 조합의 최적 보스 DPS 조합을 찾고, 그 고점의 n%는 넘어야 클리어, 증강 포함" · "모든 보스에 데미지 감소 50%" · "검은 마법사 4페이즈는 방어율로 히어로만"):
  - 체력 = 고점 × 60초 × 기준(보스별). 주니어 발록·피아누스 60% / 자쿰·혼테일·핑크빈·시그너스 50% / 스우·데미안·루시드·윌 55% / 더스크·진 힐라·듄켈 70% / 아이온·얄다바오트 60%(2체, 반씩) / 검은 마법사 2·3·4페이즈 65·70·80%.
  - **모든 보스 방어율 50%** — damage.md 8단계(남은 방어율 = 방어율 − 방무, 0 미만 0 → 데미지 × (1 − 남은 방어율))를 전투에 넣는다. 방무: 히어로 10레벨 5·20레벨 10·**50레벨 110**(어드밴스드 콤보 10 + 발할라 보스 방무 100, 합연산) / 불독 포이즌 리전 100 / 팬텀 블스아이 100 / 프리즘 '방어구 부수기' +30.
  - **검은 마법사 4페이즈 = 방어율 100%**(일반 공식 — 방무 없는 유닛은 데미지 0, 히어로 50(방무 110)·팬텀(100)은 그대로, 방어구 부수기(+30)를 받은 유닛은 30%). 사용자 7차 "히어로+증강 / 팬텀 / 방어구 부수기 셋 중 하나라도 있어야 클리어, 홀리 유니티 유무는 패스" → 체력 = 세 경로 중 가장 약한 경로(히어로 + 증강 전부, 프리즘 없이)의 60초 딜 × 80% = **2,191,928**.
  - 고점 = 그 보스 시점 표준 빌드 레벨에서 10직업 배치 + 방어 적용 + 프리즘(50레벨 유닛만, 받은 개수 — 자쿰·시그너스·스우·루시드·진 힐라에서 받아 다음 보스부터) + 그때까지 받은 증강 전부를 가장 센 유닛에(브론즈 +8%·실버 +14%·골드 +22%)를 따져 찾은 최대 보스 DPS. 홀리 유니티는 넣지 않는다(사용자 7차).
  - 대조(60초 딜 ÷ 체력, 1 이상이면 클리어): 최적 조합 = 1/기준(1.25~2.00) / 프리즘 없이 최적 직업 — 핑크빈까지 1.6~2.0, 시그너스 0.59 → 4페이즈 0.22 / 높은 레벨에 평균 직업 — 자쿰 1.21·혼테일 0.96·핑크빈 1.03, 시그너스부터 0.25 이하 / 최고 레벨 썬콜(프리즘 없음) — 피아누스 0.96·혼테일 1.07·핑크빈 1.60, 시그너스부터 0.37 이하.
  - 4페이즈 경로별(60초 딜 ÷ 체력): 히어로 + 증강 1.25 · 팬텀 + 증강 3.34 · 방어구 부수기(그 직업 프리즘 + 증강 유닛에) 1.85 → 셋 다 클리어. 아무것도 없으면 0. 증강 없는 히어로 0.26 · 증강 없는 팬텀 0.70(증강 몇 개는 필요).
- **일반**(사용자 3차 — 그대로): 라인 클리어 조합 한계(제네시스·드래곤 로어·블리자드/엘릭서 포함 사냥 최적 조합 × 프레이 × 기대 증강 × 사거리 안 0.6 × 20초 ÷ 40마리) × 테마 압박(빅토리아 14% … 세계수 40% | 아케인 소멸의 여로 86%(직전 2배 이상) … 리멘 94%), 테마 안 +3%/라운드, 한계 95% 상한.
- 수치(수입 α·아케인 배율·스페셜 목록·비용표·보스 기준·증강/프리즘 계수·압박표)는 생성 스크립트 상수 — Phase 9 실측으로 다시 맞춘다.

### 처치·정리 (#25)
- HP 0 → 즉시 대상에서 빠짐 → 사망 클립 + 사망음 → **사망 클립 길이만큼** 뒤 제거. 드랍은 처치 순간 구역 주인에게(누가 막타든 그 구역 주인).

### 필드 누적·탈락 (#26, 2026-09-23 사용자 "필드에 살아있는 수")
- 누적 = **지금 그 구역 트랙 위에 살아 있는 몹 수**. 잡으면 줄어든다. HUD 칩 `필드 n / 110`.
- 110 도달 즉시 탈락: 그 구역 몹 제거, 유닛 전부 제거(공격 루프 정지), 구역 중앙에 비석, 플레이어 목록 탈락 표시(기존 `SetPlayerAlive`), 결과 팝업.
- 보스전 동안 보관 중인 몹은 세지만 늘지 않는다(스폰 없음).

### 보스전 (#27·#28, `.info/memo.md` 사용자 규칙)
- 보스 스테이지가 되면 각 생존 구역에 그 스테이지 보스를 S에 세우고 트랙을 따라 E까지 **60초에 한 바퀴** 속도로 걷게 한다(속도 = 트랙 길이 ÷ 60). E에서 멈추고 순환하지 않는다.
- 보스는 이동 감소(빙결)·기절을 받지 않는다 — 항상 같은 속도.
- 일반 몹은 **보관**: 숨기고 멈추고 대상에서 뺀다. 보스전이 끝나면 같은 자리에서 다시 보이고 돈다.
- 보스전 동안 **모든 유닛 사거리 10 고정**(사실상 전원이 보스를 친다). 보스전 잠금 스킬은 안 쓴다(기존 `IsBossRound`가 스테이지 종류로 판단).
- 보스가 E에 닿으면 그 유저 탈락(보스 HP%는 기록). 2체(아이온·얄다바오트)는 둘 다 잡아야 하고, 두 번째는 첫째보다 1초 뒤 출발.
- 보스 처치 메소 없음. 체력바는 기존 보스 체력바(긴 막대).

### 클리어·결과·기록 (#29·#30)
- **검은 마법사 4페이즈 처치 = 클리어**. 2·3페이즈는 각자 보스 스테이지 하나.
- 결과 팝업(탈락·클리어 순간 그 유저에게): 결과(클리어 / n스테이지 탈락 — 필드 110 또는 보스 시간 초과), 도달 스테이지(순번·맵 이름), 처치 수, 보스전 탈락이면 보스 HP 깎은 비율, 개인 최고 기록. 버튼 **나가기**(2026-09-23 사용자) + **닫기**(관전 계속 — F1~F8·플레이어 목록 클릭 기존 동작).
- 나가기 = 서버가 그 유저를 월드에서 내보낸다(`_UserService:KickUser`, 사유 `WorldContent` — 엔진에 월드 종료 API가 따로 없음). Phase 8에서 로비 이동으로 교체.
- 점수 = `마지막으로 끝까지 버틴 스테이지 순번 × 100,000 + 탈락한 보스전의 보스 HP 깎은 비율(0~10,000)` — 로드맵 #30 식. 개인 최고보다 높을 때만 UserDataStorage `BestRun`에 저장(점수·순번·맵 이름·클리어 여부·날짜). 전광판 등록은 Phase 8 #42(엔진 리더보드가 ReleaseOnly).

### 영입·개발 도구
- 영입: **항상 Lv1**, 메소 안 씀. **영입 한도 = 1 + (현재 순번 ÷ 5의 몫), 최대 6** → 1·5·10·15·20·25라운드에 한 칸씩(2026-09-23 사용자 "5라운드당 1명"). 한도가 남아 있을 때만 영입(서버 검증), 방출하면 칸이 비어 다시 영입 가능. 동일 직업 불가·발판 선택 배치는 그대로. 레벨업은 기존 레벨업 버튼(드랍 메소 차감).
- 영입 버튼: 우측 패널에서 빼서 **화면 상단 가운데에 크게**(사용자). 영입할 칸이 있으면 금색 강조 + "영입 가능 n", 없으면 흐리게 + "다음 영입 n라운드". 판 시작(카운트다운) 때 영입 창을 자동으로 연다(사용자 "영입창이 활성화되어야 함"). 이후 칸이 열릴 땐 버튼 강조만(전투 중 팝업이 화면을 가리지 않게).
- 영입가 표(Phase 5 #19)는 이 규칙으로 대체될 수 있음 — Phase 5에서 정리.
- 남기는 개발 도구: 우측 하단 테스트 프리즘 버튼(Phase 4 증강이 대체), 팬텀 영입 카드(프리즘 해금 전 확인용). 둘 다 `DevTools` 플래그 하나로.
- 위치 이동 쿨타임 3분은 본 규칙대로(개발모드 0초 예외 삭제).
