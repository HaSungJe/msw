## 플랜 대비 변경점
플랜 초안(정원 r=12 / LineRenderer)은 빌드 중 사용자 지시와 실측으로 폐기했습니다. 상세는 plan 상단 "빌드 중 설계 변경" 블록에 기록.

1. **트랙 모양** — 정원 r=12 → **스타디움**(외곽 35×12.77, 코너 2.37). 사용자가 스크린샷에 그린 빨간 박스가 기준: *"사진 두개 비교해보면, 빨간색 박스 있지? 이걸 트랙으로."*
2. **트랙 파라미터** — 각도(deg) → **둘레 정규화 t∈[0,1)**. 정원이 아니어서 등속 순환에는 호길이 파라미터가 필요합니다. t=0=11시(좌상단 코너 진입), t 증가=반시계.
3. **배치 슬롯** — 동심 3링 36 → **10열×3행 30**(윗줄→아랫줄→가운데줄). 가로로 긴 스타디움 안쪽에는 링보다 그리드가 맞습니다.
4. **구역 크기** — 48×28 → **40×16**. 카메라 뷰가 42.66×24이고 HUD가 하단 31.5%를 가려 실사용 밴드가 16.44이므로, 구역 하나가 딱 그 밴드에 들어가도록 실측에 맞췄습니다.
5. **렌더 수단** — `LineRendererComponent`는 월드에서 신뢰성 있게 그려지지 않아 폐기, **스프라이트**로 대체(트랙 텍스처 1장 + 경계선 4장/구역).

## Change - 260818-1 (구역 간 여백)

**요청**: *"각자의 영역이 딱 붙어있어서 1,2는 3,4가 아래에 나오고, 3,4는 5,6이 아래에 짤려서 나와… 각각의 위치를 좀 떨어뜨려놔야할거같은데"*

**원인**: 카메라 뷰가 42.66×24인데 구역은 40×16 — 뷰가 구역보다 크므로, 구역이 딱 붙어 있으면 이웃 구역이 반드시 화면에 들어옵니다. 특히 세로는 뷰(24)가 구역 높이(16)의 1.5배라 아래 구역 절반이 그대로 보였습니다.

**구현**: `RtsConfigLogic`에 **구역 크기와 배치 간격을 분리**했습니다.
- `ZoneGapX = 8`, `ZoneGapY = 16` 추가 → `GetZonePitchX/Y()` = 크기 + 여백 = **48×32**
- `GetZoneCenter`·`GetMapCellsX/Y`가 크기 대신 **피치** 기준으로 계산 → 맵 96×128
- 구역 크기(40×16)·트랙·슬롯 좌표는 그대로. 여백은 빈 바닥입니다.

**여백 산정 근거**(앵커가 구역 중앙보다 3.8 아래 → 아래로 15.8 / 위로 8.2가 보임):
- 세로 피치 32 → 이웃 구역 경계가 위아래 24 지점 → 아래 8.2 / 위 15.8 여유로 가려짐
- 가로 피치 48 → 뷰 반폭 21.33 vs 이웃 구역 경계 28 지점 → 6.67 여유

**검증(Play Test 2026-08-18)**: 피치 48×32·맵 96×128·타일 320 ✓ / 구역 중앙 `1=(24,112) … 8=(72,16)` ✓ / **F1·F4·F8 화면 모두 자기 구역 트랙과 경계만 보이고 이웃 구역 미노출** ✓ / 맵 밖 배경도 미노출 ✓ / 빌드·런타임 에러 0건 ✓.

이전 리포트의 Remaining Issues 3번(HUD 틈으로 이웃 구역 비침)은 이 변경으로 해소됐습니다.
