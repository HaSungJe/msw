## 의도와 실제 동작
- 썬콜은 기본 AvatarRenderer/CostumeManager를 생성하지 않고 최종 PNG를 표시한다. 초기 기존 외형 번쩍임을 방지한다.
- 대기는 1장 고정이며 프레임 시계·회전·호흡·크기 변형을 사용하지 않는다.
- 체인은 0.30/0.15/0.35초, 블리자드는 0.50/1.70/0.80초 시간표를 사용한다. ReturnStand는 기존 MotionUntil 보호를 사용한다.
- 최종 자산은 wait 1장, chain-lightning 3장, blizzard 3장, portrait 1장이다. 썬콜 흉상은 선택창 140×140·상세정보 176×176이다.
- 앞선 Maker 확인: 최종 7장 RUID 순서, 체인 약 0.84초 뒤 대기 복귀, 블리자드 3.021초 뒤 대기 복귀. 중간 대기 복귀 호출에도 블리자드가 유지됐다. 실제 확대 화면과 최종 대기 PNG가 일치하고 AvatarRenderer가 없는 것을 확인했다. 사용자가 디자인·모션 일치를 확인했다.
- 앞선 마지막 로그 확인에서 빌드·실행 Error 없음. 임시 유닛 정리·일시정지 해제 확인 완료. ship 단계에서는 행동 테스트를 새로 실행하지 않았다.
- 푸시 직전 문법 확인: 이 스택에는 CLI mlua 검사기가 없으므로 Maker 빌드 로그를 확인한다. 새 Python 도구는 파일을 생성하지 않는 AST 구문 검사로 확인할 수 있다.
