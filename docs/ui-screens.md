# 화면 UI 명세 (디자인 인계용)

이 문서는 화면에 보이는 요소를 모두 정리한 것이다. 요소마다 누가 어디서 만드는지, 어디에 어떤 크기로 놓이는지, 색·글꼴, 언제 보이는지, 누르면 무엇을 하는지를 적었다. 읽는 사람은 ChatGPT(디자인 담당)이고, 이 문서만 보고 게임 로직을 깨지 않고 화면을 다시 꾸밀 수 있게 하는 것이 목적이다.
- 현재 PC/모바일 배치는 문서 끝의 **PC·모바일 공통 런타임 배치**와 `docs/design/mobile-ui.md`가 기준이다. 아래 과거 HUD 도면·좌표표(2~3절)는 기존 엔티티/기능 추적용이며 새 표시 좌표를 뜻하지 않는다.
- 기존 조사 기준 코드: `RootDesk/MyDesk/*.mlua` (2026-09-24, 커밋 a75a69f 이후 작업 트리). 표기는 `파일:줄` 형식이며 파일 접두 `RootDesk/MyDesk/`는 생략했다.
- 읽는 순서: `.beaver/memory/` → `AGENTS.md` → 이 문서. 엔진 관례는 `docs/msw-engine.md`를 본다.
- 시각 방향·공통 색·컴포넌트·Claude Code 구현 인계는 `docs/design-system.md`를 본다. 화면의 실제 동작과 좌표는 이 문서가 기준이다.
- 기본은 현재 라이트모드다. 우측 하단 라이트·다크 스위치의 선택형 다크모드는 서버 계정 설정 `uiMode`로 저장·복원한다. 아래 라이트 색값의 다크 대응과 검증 상태는 `docs/design/ui-dark-mode.md`를 따른다. 모드 전환은 렌더러 색만 바꾸며 열린 창·탭·스크롤을 유지한다.

## 1. 개요

### 1.1 기본 전제
- 기준 해상도는 **1920×1080**이다. 모든 UI 좌표는 이 해상도의 px 값이다(RtsHudLogic:5, RtsPopupLogic:4).
- `.ui` 파일은 없다. UI는 **전부 mlua 스크립트가 런타임에 스폰**한다. 엔진의 `/ui` 엔티티를 찾고(RtsHudLogic:284), 그 아래에 두 그룹을 만든다.
  - `RtsHudGroup`(`_RtsHudLogic.HudGroup`, RtsHudLogic:292): HUD, 캐릭터 클릭 메뉴, 몬스터 정보, 난이도 막대가 여기 붙는다.
  - `RtsPopupGroup`(`_RtsPopupLogic.Group`, RtsPopupLogic:73): 팝업 셸이 붙는다. HUD를 다 만든 뒤 `_RtsPopupLogic:Build(ui)`로 생성된다(RtsHudLogic:466).
  - **두 그룹 모두 만든 직후 `_RtsHudLogic:StretchFull(grp)`로 화면 전체(anchor 0,0~1,1, 오프셋 0)로 늘린다.** 안 하면 실제 클라이언트에서 그룹이 작은 기본 크기로 화면 가운데에 생겨 모서리 요소가 전부 가운데로 몰린다(2026-09-24 v260924-1 출시 화면에서 발견 — Maker Play에서는 드러나지 않음). 새 UI 그룹을 만들 때도 똑같이 한다.
- HUD를 만드는 시점: 로컬 플레이어의 카메라 앵커가 클라에서 시작할 때 `RtsCameraAnchorComponent.SetupClient` → `_RtsHudLogic:BuildHud`(RtsCameraAnchorComponent:46)가 한 번 호출된다.
- 쓰는 모델: `model://uigroup`, `model://uisprite`, `model://uitext`, `model://uibutton`, `model://uiempty`(유닛 외형 미리보기).

### 1.2 좌표계 (UITransformComponent)
| 값 | 의미 |
|---|---|
| `AnchorsMin = AnchorsMax = anchor` | 부모 사각형 안의 기준점. (0,0)=왼쪽 아래, (1,1)=오른쪽 위, (0.5,0.5)=가운데 |
| `Pivot` | 자기 사각형 안의 기준점. 위치가 이 점을 기준으로 잡힌다 |
| `anchoredPosition` | anchor에서 pivot까지의 거리(px). **+x는 오른쪽, +y는 위쪽**이다. 그래서 위쪽 anchor에 붙는 요소는 y가 음수다 |
| `RectSize` | 폭×높이(px) |
| 스트레치(`OffsetMin`/`OffsetMax`) | anchor 구간(`aMin`~`aMax`)에 맞춰 늘어난다. 왼쪽 아래 여백은 OffsetMin, 오른쪽 위 여백은 OffsetMax(음수 = 안쪽)로 준다 |

이 문서의 표기: `a(0,1) p(0,1) (16,-16) 440×112` = anchor (0,1), pivot (0,1), 위치 (16,-16), 크기 440×112. 화면 절대 좌표는 **왼쪽 위를 원점**으로 쓴다. 코드의 UI 좌표는 아래로 갈수록 y가 줄어든다는 점에 주의한다.

월드 위치를 UI 위치로 바꿀 때는 `_UILogic:ScreenToUIPosition(_UILogic:WorldToScreenPosition(v))`를 쓴다. 결과는 화면 중앙을 원점으로 하는 좌표라서, HUD 그룹 자식에 anchor (0.5,0.5)로 그대로 넣는다(RtsUnitSelectLogic:139-141, docs/msw-engine.md:31).

### 1.7 텍스트 관례
- **모든 라벨은 BestFit**(2026-09-24): `SpawnLabel`이 `TextComponent.BestFit = true`, `MaxSize` = 지정 크기, `MinSize` = 60%(최소 9)로 만든다. 글이 칸보다 길면 넘치거나 두 줄로 꺾여 겹치지 않고 칸 안에서 작아진다. 글자 크기를 나중에 바꿀 땐 `FontSize`가 아니라 `_RtsHudLogic:SetLabelSize(e, size)`(MaxSize까지 같이)를 쓴다. 칸 크기는 여전히 넉넉히 잡는다(BestFit은 마지막 안전망).
- 정보 카드(2026-09-24): 440×138 — 윗줄 라운드·시간 / 둘째 줄 '지역 - 맵'(412px) / 셋째 줄 난이도(금색 15) / 구분선 y −94 / 아랫줄 메소·필드. 플레이어 목록은 y −166부터. → **2026-09-25 프로필 상자와 합쳐 좌상단 상자 400×240(배경 = 테마 썸네일) 안 정보 칸으로 — 3.0·3.1**
- 한 줄 라벨이 넘치면 `Overflow = OverflowType.Truncate`로 자른다. `ellipsis` 모드에는 긴 새 글이 오면 이전 글이 그대로 남는 버그가 있다(docs/msw-engine.md:22-24, RtsHudLogic:391).
- **Truncate와 리치텍스트는 같이 쓰지 않는다.** 태그가 잘려서 그대로 드러나기 때문에 잘릴 수 있는 라벨은 평문으로 둔다(RtsHudLogic:975). `UseNBSP = true`를 켜면 단어 중간에서 줄이 끊기지 않는다.
- 이모지는 게임 글꼴에 없어서 안 그려진다(실측, RtsUnitPopupLogic:579). `✓ ▾ ▴ ▼ ▲ · —` 같은 기호는 쓰고 있다.
- 글자 폭을 잴 수 없다. 여러 줄 설명의 높이는 어림으로 계산한다(`DescLines`: 14px 글꼴 기준 한글 13px, 그 외 8px, 1~3줄, RtsUnitPopupLogic:414-427).
- 숫자를 화면에 보일 때는 `Int()`/`FormatNumber()`를 쓴다. 동기화된 number를 `tostring`하면 "1.0"이 된다(AGENTS.md, docs/msw-engine.md:26-28).

## 4. 팝업 (RtsPopupLogic)

### 4.1 셸 구조

- `RtsPopupGroup` 아래 화면 전체 딤, 가운데 `RtsPopupPanel`, 70px 제목 영역, 투명 본문 `RtsPopupBody`를 둔다. 바깥 백색 반투명 패널 위에 흰 물결을 한 번만 깔고 글자는 짙은 회색, 선택은 연보라색이다.

### 4.4 나머지 팝업 세부
**영입 (`BuildRecruit/BuildRecruitCards`)**

영입창을 열 때마다 모험가 탭을 기본 선택한다. 열린 창 안에서 탭을 바꾸거나 목록만 갱신할 때는 현재 선택을 유지한다.

모험가/영웅 탭 아래 **전사 / 궁수 / 마법사 / 도적 / 해적** 5열을 항상 같은 순서로 표시한다. 직업군 제목은 각 열 중앙 정렬이다. 팝업1320×760, 열 폭243.6·간격12, 카드243.6×132, 행 간격144로 줄였다. 출시된 직업이 없는 열도 머리글과 선택 불가한 ‘출시 예정’ 카드를 둔다. 팬텀은 영웅 탭의 도적 열에 배치한다. 현재 11직업 모두 전용 흉상84×84를 사용한다. 그림 아래 공식 직업명20px을 표시하고 레벨은 카드·하단 안내에서 제거했다. 보유 중 상태만13px로 남기며, 잠김은 문구 대신 흉상 중앙에 36×44px 자물쇠를 58% 불투명도로 겹친다. 아이콘은 클릭을 가로채지 않는다. 상태가 없는 카드는 그림·이름을8px 내려 세로 중앙에 맞춘다. 보유·잠김 상태도 상세 열기는 가능하며 영입 검증은 기존 로직이다. 영입 상세도 같은 흉상을 사용한다.

계열 탭은 `RtsJobTableLogic.GetRecruitFactions`, 소속은 `GetJobFaction`, 5열 구성은 `GetRecruitGroups`에서 공급한다. 이후 레지스탕스·시그너스 기사단·레프 등을 등록해도 같은 5열 레이아웃을 재사용한다. 아직 등록하지 않은 계열의 탭은 미리 노출하지 않는다.

Maker Play에서 두 탭의 5열·빈 카드·팬텀 도적 열 배치를 캡처로 확인했다. 모험가/영웅/미등록 계열 모두 5개 열을 반환하는 검사와 런타임 오류 0을 확인했다.

**증강 보유 (`BuildAugment`)**

통합 메뉴 아래 전체 개수와 적용된 증강 숨기기 체크가 있다. 보유 등급 탭은 제거했다. 왼쪽 목록 폭440, 행424×86. 등급/속성 합성 아이콘64px, 이름18px, 미지정 또는 적용 직업을 표시한다. 미지정은 위로 정렬한다. 선택은 연보라 테두리이며 목록을 다시 만들지 않는다.

오른쪽 상세는 배지·이름23px·효과18px → 대상 안내 → 2열 캐릭터 버튼64px → 지정 버튼52px. 효과 공간176px, 대상은 최대6개. 하단에 전체/미지정 개수와 방출 시 소멸 안내가 있다. 행 선택은 `RestyleAugRows/RefreshAugDetail`, 동기화는 `RefreshAugment`, 숨기기는 `ApplyAugFilter`가 기존 행을 켜고 끈다.

**뽑기 (`BuildDraw/RefreshDraw`)**

보유 메소, 브론즈·실버·골드의 다음 뽑기 확률, 프리즘 카드의 확정까지 남은 횟수('13회' — 확정 20·40번째 — 다음이 확정이면 안내 '다음 뽑기가 프리즘 확정!', 두 번 다 지나면 '-'), 가격 규칙(1회차 3,200부터 뽑을 때마다 +200 · 20회차부터 7,000 고정), 선택 대기 수를 표시한다(2026-09-28 개편 — 전: 프리즘 %·남은 수·천장). 브·실·골 확률은 `BuyPrismRate`(확정 차례면 100 → 나머지 0)와 서버의 일반 등급 비율(브 50 · 실 40 · 골 10)로 계산하고, 프리즘 카드 글자·안내는 `DrawRefs.rates[4]`·`hints[4]`만 바꾼다. 뽑기 버튼470×76은 가격·메소 부족·한도·일시정지 상태를 표시하고 기존 `BuyFromHud/RequestBuy`로 요청한다. 뽑기가 처리되면(뽑기 횟수 증가 — `AwaitBuy`, 3초 안에 안 오르면 대기 해제) 획득음(`PickSound`)과 함께 **보유 증강** 탭 바탕이 금색으로 두 번 반짝인다(`FlashHubTab`, 0.8초). 뽑기 페이지는 그대로 유지한다. 값이 바뀌면 해당 라벨만 갱신한다.

**증강 도감 (`BuildCodex`)**

등급 필터44px, 안내16px, 세로 목록. 기본 행96px에 이름·효과·확률을 분리한다 — 브론즈~골드의 오른쪽 %는 그 단계가 나올 확률(I 50 · II 35 · III 15%, `LevelWeights` — 종류는 고르므로, 2026-09-27. 전: 등급 안 가중치 확률), 안내 줄 = '라운드 지급 7장(III) · 기본 뽑기 확률 50%'(실버 7장 · 40%, 골드 3장 · 10% — 2026-09-28) + 끝에 '뽑기 단계 I 50% · II 35% · III 15%(라운드 지급은 항상 III), 종류는 선택'. 프리즘 행은 직업 배지·이름·펼치기로 구성하며 오른쪽 %는 프리즘 안 가중치 확률(3택1 — 안내 줄 '자쿰 처치 뒤 원하는 것 선택 · 시그너스 · 루시드 처치 뒤 · 뽑기는 3택1', 2026-09-27), 펼친 설명 높이는 실제 텍스트의 추정 줄 수×24+여백으로 계산한다. 펼치기는 해당 행 크기만 바꾼다. 안내의 고정 확률은 ‘기본 뽑기 확률’로 명시하고 현재 확률은 뽑기 탭에서 확인한다.

**증강 선택 (`BuildPick`)**

보유 탭의 미선택 증강을 열면 선택지 카드를 표시한다. 브론즈~골드는 단계(I/II/III)만 무작위이고 그 단계의 종류 전부(`StatChoices` — 4장, 골드 III만 5장)를 높이 660 카드로 한 줄에 늘어놓는다 — 카드 폭 = (1060 − 19 × (장 수 − 1)) ÷ 장 수(4장 250 · 5장 196), 제목·안내 '<등급> 증강 <단계> 선택 · 원하는 증강을 하나 골라 주세요', 카드 윗줄 '<등급> <단계>'(`GradeLevelName`)(2026-09-27 사용자 개편 — 전: 340×660 세 장). 프리즘은 가중치 무작위 3장을 340×660으로(제목 '프리즘 증강 선택'). 자쿰이 준 프리즘만 아직 없는 프리즘 전체(`PrismChoices` — 내 유닛 직업 → 다른 직업 → 특수 코어 → 팬텀)를 340×600 카드로 가로 스크롤(`RtsPickScroll`, 칸 간격 19, 막대 10 — 선택지가 3장보다 많을 때, 안내 '좌우로 넘겨 보기 · n종')에 늘어놓는다(2026-09-27 사용자 "자쿰 한정으로 자쿰이 준 프리즘만 선택 가능"). 서버는 선택 번호를 선택지 수까지 받는다. 등급 띠·104px 합성 아이콘, 이름21px, 효과18px(카드 폭 − 38 × 230), 받기(카드 폭 − 38)×44. 아이콘·제목·설명의 시작 높이는 설명 길이에 관계없이 고정한다. 지속 반짝임 타이머는 제거하고 정적인 등급색 가장자리·등장음을 사용한다.

**캐릭터 칩 줄**(2026-09-28 사용자 "증강 종류 선택부분에서 직업 선택 — 마지막에 선택한 것 자동 선택, 없거나 방출됐다면 미지정"): 안내 줄(−4, 높이 36) 아래 −44에 높이 60 칩을 가운데 정렬로 늘어놓는다 — [지정 안 함 · 보유 증강으로] + 내 유닛(번호 순, 계열색 띠 · 직업명 · 'Lv. n · 증강 n/30'). 칩 폭 = min(200, (1306 − 10 × (칩 수 − 1)) ÷ 칩 수). 고른 칩은 금색(`RefreshPickTargets` — 칩 색·받기 글자만 제자리 갱신). 고른 유닛은 `RtsAugmentLogic.PickNo`·엔티티 Id로 기억해 다음 선택 창에서도 골라져 있고, 방출·교체·증강 30개 가득이면 '지정 안 함'으로 돌아간다(`PickTarget`). 가득 찬 유닛 칩은 흐리게·클릭 없음('증강 30개 가득'). 카드는 −112부터 420×474(아이콘 88 y−40 · 이름 y−134 · 설명 y−194 높이 170 · 받기 88).

## 6. 상태별 화면 변화

`RtsStageLogic.RunState`(@Sync)는 `idle` → `countdown`(15초, RtsStageLogic:21) → `running` → `ended` 순으로 바뀐다. HUD는 `RtsStageLogic.RefreshHud`가 0.25초마다(:90, :434-475), 증강 쪽은 `RtsAugmentLogic.ClientTick`이 0.3초마다, 난이도 막대는 `RtsDifficultyLogic.ClientTick`이 0.3초마다 갱신한다.

| 요소 | idle | countdown | running | ended |
|---|---|---|---|---|
| 정보 카드 윗줄 | 대기 중 | 시작까지 + 초 | n라운드 / 보스 / 쉬는 시간 / 보스 준비 | 게임 종료 |
| 난이도 막대(F) | 보임 | 보임 + '바로 시작' | 숨김 | 숨김 (:136) |
| 다시 하기(D) | 흐림(idle 모드), 눌러도 무시 | 〃 | 여럿이면 3초 확인, 방에 혼자(솔로)면 바로 새 판 | 누르면 바로 찬성(혼자면 바로 새 판) |
| 투표 패널(E) | 표가 있을 때만 | 〃 | 〃 | 〃 |
| 영입 버튼(R) | 숨김 | 숨김 | 빈 칸이 있을 때만 "영입 가능 n" | 솔로 "다시 하기"(금색) / 여럿 "나가기" |
| 영입 팝업 자동 열기 | — | — | 첫 틱에 한 번(살아 있을 때) | — |
| 증강 뽑기(Y) | 흐림 | 가능하면 금색 | 가능하면 금색 | 흐림 |
| 증강 선택 팝업 | — | 선택지가 오면 자동 | 선택지가 오면 자동(접어 두면 '펼치기') | — |
| 안내(H) | — | — | 보스 준비 초읽기(1.2초씩) | 끝난 순간 한 번 "게임 종료 — …"(6초) |
| 슬롯·증강·도감·목록 | 항상 | 항상 | 항상 | 항상 |

**탈락·클리어한 나** (`RtsRunResultLogic.StateByUser` 1·2, `IsMeAlive()` = false)
- 결과 팝업이 자동으로 뜬다(본인에게만).
- 영입 버튼 자리가 솔로면 "다시 하기"(금색, 누르면 바로 새 판), 여럿이면 "나가기"(위험색)로 바뀐다(`RtsHudLogic.RefreshRecruitButton` exitMode).
- 뽑기는 클라에서 막히고(RtsAugmentLogic:374), 영입 카드는 누를 수 없다.
- 플레이어 목록에서 내 행이 비석과 회색으로 바뀐다. 구역 가운데에는 비석 월드 스프라이트가 선다.
- 탈락이면 배경음이 꺼진다. 살아 있는 구역을 관전 중이면 그 곡이 나온다(RtsStageLogic:487-496).
- 난이도 막대는 idle·countdown에만 보이므로 관전 중에는 나오지 않는다.

**관전(다른 구역 보기)** — F1~F8(RtsCameraAnchorComponent:132-136) 또는 플레이어 행 클릭
- `JumpToZone` → `SetWatchedZone`이 불리고, 보고 있는 행의 테두리가 금색이 된다.
- 몬스터 정보는 **보고 있는 구역**의 몬스터를 잡는다.
- 유닛 클릭 판정은 **내 구역 유닛만** 본다(RtsUnitSelectLogic:67). 그래서 남의 유닛은 눌러도 반응이 없다. 우측 슬롯도 계속 내 유닛을 보여 준다. 결과적으로 관전은 읽기 전용이다. 조작 RPC는 서버가 `senderUserId`로 다시 검증한다.
- 로드맵은 "관전 중 상세보기"를 말하지만(roadmap:55), 지금 코드에는 남의 유닛 상세를 여는 경로가 없다.

**보스전**
- 보스 준비(`BossPrep`, 5초): 카드가 "보스 준비"로 바뀌고 안내에 "○○ 등장까지 n초"가 뜬다.
- 보스 라운드: 카드가 "보스"로 바뀐다. 보스는 맵 가운데 붉은 보스 영역(2×2칸)에 바로 나타나 고정으로 서고(그림은 3×3칸 크기로 둘레 발판에 조금 걸침), 긴 체력바가 붙는다. 겹치는 자리의 유닛이 보스 위에 보이고 클릭도 유닛이 먼저다. 몬스터 정보에 "보스" 딱지와 방어율이 보인다.
- 60초 안에 못 잡으면 결과가 "탈락 — 보스 시간 초과"가 된다. 보스를 잡은 뒤 프리즘 선택지가 오면 제목이 "프리즘 증강 선택"이다 — 자쿰은 아직 없는 프리즘 전체(가로 스크롤), 시그너스·루시드는 3택1.

**모드 (클라 전용)**
- 위치 이동 모드와 영입 배치 모드에서는 발판 틀이 켜지고 안내가 계속 떠 있다. ESC로 취소한다.
- 팝업을 열면 배치 모드가 끝난다. 유닛 팝업을 열면 이동 모드·배치 모드·메뉴가 모두 끝난다(RtsUnitPopupLogic:59-61).

### 7.3 작업 요령
- **바뀐 칸만 다시 그린다 — 창 전체를 다시 열지 않는다**(2026-09-25 사용자 "화면 내용 바뀔 때마다 필요한 부분만 재랜더링하고 나머지 부분 좀 그만 건드려"): 탭 전환·선택·서버 값 갱신으로 일부가 바뀌면 `Open(같은 kind)`를 부르지 말고
  - 탭 줄 = `RtsPopupLogic.SpawnTabBar`(누르면 제자리에서 켜짐만 — `BarSelect`·`SetTabOn`, 글자는 `SetTabText`, Tab 키 순환 `BarNext`)
  - 바뀌는 목록·상세 = 투명 컨테이너(`SpawnBox`)째 새로 만들고 옛 것은 `DropLater`(0.12초 뒤 지움)
  - 선택 표시(행 색·체크 칸·아이콘 칸 색)는 참조를 들고 있다가 제자리에서 색만(`RestyleAugRows`·`RefreshPresetMarks`·`RefreshIconCells`)
  - 예: 증강 창(`RefreshAugment` = 목록·상세·아래 줄, 행 클릭 = 행 색 + `RefreshAugDetail`), 도감(`RefreshCodex`), 영입 목록(`RefreshRecruit`), 영입 상세(`BuildRiSkills`), 프로필(`RefreshProfileContent`), 유닛 상세(`RenderRight` — 외형은 직업·프리즘 이름이 바뀔 때만 `Render`)
- UI 아바타(`AvatarGUIRendererComponent`, `RtsUnitPopupLogic.SpawnPreviewAt`)는 칸 **아래쪽에** 서서 칸이 크면 위가 빈다 — 칸을 캐릭터 크기에 맞게 낮게, 두손검·창은 캐릭터 왼쪽으로 길게 나오니 칸 안쪽으로(2026-09-25 실측)
- 화면 문구에 개발용 분류(티어·서포터·1티어 등)를 쓰지 않는다(메모리 workflow) — 증강 효율은 오각형 모양으로만
- **다시 그리기는 번쩍이지 않게**(2026-09-24): 같은 팝업을 다시 그릴 때(`RtsPopupLogic.Open`이 같은 kind로 불릴 때) 팝업 그룹은 끄지 않고 옛 body를 0.12초 남겼다가 지운다(`OldBody`/`KeepOldBody`). 유닛 창 `Render`도 옛 `Content`를 0.12초 뒤에 지운다. 엔진이 UI를 여러 프레임에 나눠 만들기 때문에, 지우자마자 새로 만들면 빈 창이 한순간 보인다 — 새 화면 코드도 같은 방식을 쓴다.
- 자기 효과음이 따로 있는 버튼은 `SpawnClickQuiet`(클릭음 없음)로 만든다(예: HUD '펼치기' — 증강 선택 등장음과 겹쳤다).
- UI 코드만 고치는 작업은 `@ExecSpace("ClientOnly")`(또는 `Client`) 메서드 안에서 끝낸다. 대상은 `Build*`, `Apply*`, `Refresh*`, `Set*`, `Spawn*` 계열이다. 새 스크립트가 필요하면 PascalCase에 `Logic`/`Component` 접미사를 붙이고 서버·클라이언트 경계를 넘는 메서드의 실행 공간을 명시한다. 공용 계산 메서드에는 주석이 없는 기존 사례도 있다(`RootDesk/MyDesk/RtsStageLogic.mlua:103-130`).
- mlua API가 불확실하면 추측하지 말고 msw-mcp `mlua_api_retriever`로 확인한다. 런타임 이름이 선언 파일과 다른 경우가 있다. 예: 스크롤바는 `ScrollBar*`(RtsUnitPopupLogic:629). `AutoHide`/`Hide`는 쓰지 않는다(:613).
- 엔진 동작 실측(텍스트 Truncate, 업로드 스프라이트 PPU, UI 좌표 변환, 입력)은 `docs/msw-engine.md`에 있다.
- 목업 `.info/artifacts/hud-layout.html`(v16)과 플레이어 카드 스케치 `.info/artifacts/player-slot-sketch-260922.png`는 **로컬 전용**(.gitignore)이라 다른 기기에는 없을 수 있다. 목업이 실제와 다르면 **이 문서와 코드가 기준**이다.
- 검증 순서(docs/testing.md): `maker_stop` → **`maker_refresh_workspace`** → `maker_save` → `maker_play` → `maker_logs(kind:"build")`로 문법 확인 → `maker_logs(kind:"normal")`로 런타임 확인 → `maker_screenshot` → `maker_stop`. refresh를 빼먹으면 옛 스크립트로 돈다. 문법 오류는 `[LEA-3016] InvalidFormat …`으로 normal 로그에 찍힐 수 있다(.beaver/memory/msw-engine.md:163).
- UI를 바꾸면 이 문서의 해당 표도 같이 고친다(.beaver/memory/balance.md:313).

### 7.4 알려진 어긋남 (손대기 전에 확인)
- 안내 문구 "영입 버튼 옆 '다시 하기'"(RtsStageLogic:472, RtsRunResultLogic:340)는 현재 배치와 맞지 않는다. 영입 버튼은 오른쪽 슬롯 아래에 있고 다시 하기는 위쪽 가운데 오른편에 있다. 주석 RtsHudLogic:4·:699·:710과 RtsDifficultyLogic:14·:150의 "상단 가운데 영입 버튼"도 옛 배치 기준이다.
- 안내(H)와 난이도 막대(F)가 같은 자리를 쓴다(2장).
- `RtsHudLogic.SetPlayerAlive`(:927)는 부르는 곳이 없다. 목록은 매번 서버 통지로 전부 다시 만든다.
- `@ExecSpace` 표기가 어긋난 곳이 있다. RtsUnitPopupLogic:412의 표기는 주석 너머 `DescLines`에 붙어 있어서 `BuildTargetRow`(:429)에는 표기가 없다. RtsPopupLogic:975-977에는 같은 표기가 두 번 있다. 동작에는 문제가 없지만 옮길 때 주의한다.

### 백색 물결 UI의 추가 공통 규칙

- 등급 문양과 속성 그림은 `SpawnAugIcon`의 고정 크기 부모/자식으로 합친다. 직업 프리즘11종은 공식 스킬 그림, 공통 프리즘은 해당 능력치 그림이다. 캐릭터 증강 행도 같은 구조이며 텍스트 줄바꿈에 아이콘이 영향을 받지 않는다.
- 캐릭터 능력치 도형은 고정 축 기준(공격력1000·공격력 증가200%·최종300%·보스200%·크리 확률100%·크리 데미지200%)을 사용한다. 범위를 넘으면 도형만 제한하고 실제 숫자는 그대로 표시한다.
- 도감 프리즘은 아이콘68px 아래 y96부터 설명을 펼친다. 행 높이도 설명 길이에 맞춰 늘린다.
- 반투명 컨테이너 교체는 `SwapContent`로 준비 단계의 alpha/입력을 차단해 두 면이 겹치는 밝기 변화를 막는다.
- 난이도 막대는 높이138(난이도 줄 + 모드 줄 — 2026-09-28, 전 92), 버튼42이며 idle·countdown에만 표시한다. 바로 시작은 아래에 유지하고 running·ended의 다시하기는 막대가 사라진 상단 중앙 자리에 표시한다. 우측 슬롯 아래 중복 다시하기는 없다.

### 프로필·증강 정렬 추가 반영
- 프로필 설정/테마·비석 확인/아이콘 상세·확인·획득창의 셸은 alpha1이다. 흰 물결 장식은 유지하지만 맵은 비치지 않는다. 좌상단 프로필·정보 상자도 alpha1이며 테마 썸네일 배경을 제거했다.
- 증강 선택 카드: 등급(y-12)·아이콘(y-150)·이름(y-274)·효과(y-350)가 같은 가로 중앙 축이다. 효과는 UpperCenter로 시작 높이를 맞추며 받기 버튼과 분리한다.
- 보유 증강 행: 아이콘64px, 이름226×48과 미지정86×26을 세로 중앙(y0)에 맞춘다. 이름은 왼쪽 정렬, 배지는 오른쪽이다.
- 대상 선택: 직업명은 왼쪽, Lv. 레벨은 오른쪽62px 독립 칸에 한 줄로 표시한다. ‘1.’·‘2.’ 같은 유닛 번호와 강제 줄바꿈을 제거했다.

- 증강 선택 카드 고정 배치: 카드 340×660, 등급은 상단·받기는 하단 유지. 인레이지·트루 스나이핑의 기존 높이를 기준으로 아이콘104는 y-150, 제목302×64는 y-274에 고정한다. 설명302×230은 y-350에서 UpperCenter로 시작한다. 제목은 MiddleCenter이며 설명 길이로 묶음 전체를 세로 중앙에 재배치하지 않는다.

## 보유 증강·미선택 증강·유닛 목록

- 보유 탭 왼쪽 목록에 미선택 증강을 한 건씩 표시한다. 각 행은 등급 문양·공통 선택 아이콘·등급명·미선택 표시로 구성하며, 적용된 증강 숨기기와 관계없이 보인다. 원하는 행을 누르면 해당 건의 선택지를 열고, 받으면 보유 목록의 미지정 증강이 되어 유닛에 지정할 수 있다. 받은 증강과 미선택 건수는 구분한다.
- 증강 뽑기 탭은 구매 전용이다. 미선택 증강이 있어도 선택 화면으로 바뀌지 않고 구매 후에도 뽑기 페이지를 유지한다. 뽑기가 처리되면 획득음 + 보유 증강 탭 금색 반짝임으로 알린다(2026-09-26 사용자 "뽑았다는 사운드, 보유 증강 탭에 이펙트 살짝"). 선택 화면은 보유 탭에 속한다. 증강 입구는 항상 보유 탭을 연다.
- 우측 유닛 목록은 방출 후 내부 유닛 번호 순으로 위쪽부터 빈칸 없이 표시한다. 직업명 앞 번호는 모두 제거한다. 행 클릭·선택은 원래 유닛 번호를 보존한다.
- 몬스터·보스 상태창은 백색 물결의 640×208 둥근 패널이다. 왼쪽 96px 초상, 오른쪽 이름·종류 배지·체력 수치·10px 체력바·라운드/맵과 방어율(보스 · 방어율이 있는 일반 몬스터 — 2026-09-26 아케인리버 50%), 아래 디버프 칩을 분리한다. 디버프 설명도 같은 밝은 디자인이다. 디버프 이름은 거는 스킬 이름(블리자드·블리자드 템페스트·디바인 퍼니시먼트·포이즌 리전·가드 크러쉬·방어구 부수기), 설명은 효과만 쓴다(스킬 이름을 다시 붙이지 않음 — 2026-09-27 사용자).
## PC·모바일 공통 런타임 배치

`RootDesk/MyDesk/UI/RtsUiLayoutLogic.mlua`가 기존 HUD 엔티티를 재배치한다. 서버 게임 규칙·가격·계정 저장 계약은 유지한다. 아래 좌우 배치는 상·하단 바를 사용했던 HTML 시안보다 우선하는 현재 구현이다.

- 가로 화면을 지원하며 실제 화면을 `ScreenToUIPosition`으로 측정하고 높이/1080 배율을 사용한다. 전투판·캐릭터는 종횡비를 유지하고 배경은 화면을 채운다.
- 좁은 화면(폴더블 펼침·태블릿 등 약 1.57:1보다 좁은 비율 — 2026-09-28 모바일 사용자 제보, 약 1.1:1에서 윗줄의 정보 카드·난이도 줄·오른쪽 버튼이 겹침): 배율 = min(높이/1080, 가로/(1640 + 좌우 여백)) — `RtsHudLogic.LayoutMinWidth` = 왼쪽340 + 20 + 난이도 줄960 + 20 + 오른쪽300. 배치는 그대로 두고 전체를 비율대로 줄인다. 휴대폰 가로(16:9~21:9)·PC 16:9는 이 조건에 걸리지 않아 그대로. Maker에서 이 값을 2600으로 올려 좁은 화면을 흉내 내 PC·모바일 미리보기 모두 겹침 없음 확인
- 모바일 태블릿·폴더블(16:9보다 좁은 모바일 화면): 버튼·패널이 화면 가로에서 차지하는 몫을 휴대폰 19.5:9와 같게 — 배율 = min(위 값, 가로/2340)(`RtsHudLogic.TabletPhoneWidth`). 좌우 버튼 줄이 좁아진 만큼 트랙이 커진다(폴더블 약 1.2:1 배율 1.48 → 0.82 · 트랙 약 1.6배, 태블릿 4:3 1.33 → 0.82 · 약 1.4배). 버튼 실제 크기는 휴대폰과 비슷(폴더블 약 6mm). 2026-09-28 사용자 "폴더블/태블릿에서 버튼 UI 크기를 좀 더 작게 하고 트랙을 키우는 게" — PC의 좁은 창은 위 가로 맞춤만

### 검증 범위

Maker에서 유닛3명 페이지의 다음/이전·양끝 비활성·항목 감소 보정, 보유 증강 필터의4→3페이지 보정과 선택 유지, 지정 대상2/3, 도감 설명 펼침 후 항목 유지, 증강 선택2/2의 원래 후보4·5 연결을 확인했다. 모바일 분기에서 긴 프리즘 설명과3/5 페이지도 시각 확인했다.

이전 전체 화면 개편에서 Maker 주요 팝업과 임시 증강 수령·지정을 확인했다. 이번 좌우 배치의 Maker PC·모바일 분기 HUD, 캐릭터 선택·배치 안내를 확인했다. 208칸 화면↔보드 좌표 왕복 최대 오차는0.0000839233월드 단위였다. 이전 배치 검증 당시 버튼 위치(왼쪽 위 설정·인원 포함 유저 목록, 왼쪽 아래 다시하기/일시정지·배속)는 최종 PC 재생 화면과 빌드·실행 오류0을 확인했다. 모바일 실기기에서는 최종 위치를 추가 확인해야 한다. 실제 갤럭시·아이폰 터치·노치 및 멀티플레이는 별도 검증 대상이며 Maker 미리보기를 실기기 확인으로 표기하지 않는다. 검증용 유닛과 Preview는 재시작으로 정리했다. 최종 화면 확인 중 사용자가 영입한 유닛은 유지하며 월드는 게시하지 않았다.

### 첫 영입 취소 후 재진입

게임 시작 후 ESC로 자동 영입창을 닫아도 영입 기회는 유지한다. 오른쪽 영입 버튼으로 다시 열 수 있고, 보유 유닛0명·영입 가능 상태에서 유닛 버튼은 `유닛 영입`으로 표시하여 영입창을 연다. 보유 유닛이 있는 경우에는 유닛 창에 `캐릭터 영입 · n명 가능` 버튼을 표시한다.
