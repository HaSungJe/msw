# 디자인 인계 — ChatGPT(이미지·가이드라인) → Claude(구현)

> 2026-09-25 사용자: "ChatGPT에서 이미지 생성은 직접 하고, 그 외 UI 같은 것들 디자인적 조절할 때는 가이드라인을 만들어서 Claude가 이어받을 수 있게."
> **시각 기준(색 토큰·글자 크기·컴포넌트 상태·화면 우선순위·첫 구현 범위)은 `docs/design-system.md`(ChatGPT 작성)** — 이 문서는 그 위에서 주제별 가이드라인을 주고받는 **양식과 파일 자리**만 정한다.
> 화면 요소 이름·크기·만드는 곳은 `docs/ui-screens.md`, 테마·비석 프리셋은 `docs/theme-presets.md`, 엔진 관례는 `docs/msw-engine.md`.

## 1. 역할
| 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|
| ChatGPT | 이미지 생성(아이콘·썸네일·배경·프레임·버튼 등), 디자인 가이드라인 작성(색·크기·배치·글꼴·상태별 모양) | 게임 코드(.mlua) 수정, 리소스 업로드, Maker Play 조작 — 가이드라인에 "이렇게 바꿔 달라"로 적는다 |
| Claude | 가이드라인을 읽고 이미지를 **새 리소스로** 업로드 → 코드 반영 → Maker에서 확인 → 문서 표 갱신 → 가이드라인 상태를 '구현됨'으로 | 가이드라인에 없는 디자인 판단(모르면 사용자에게 묻는다) |

## 2. 파일 두는 곳
- 이미지: `assets/design/<YYMMDD>-<주제>/` — 원본 PNG(투명 배경이면 알파 포함). 파일명은 쓰임이 보이게(`profile-card-frame.png`, `icon-slot-bg.png`)
- 가이드라인: `docs/design/<YYMMDD>-<주제>.md` — 아래 3절 양식 한 장에 한 주제(예: `260926-profile-window.md`, `260926-skill-list.md`)
- 한 주제 = 한 번에 구현·확인할 수 있는 크기(창 하나, 버튼 한 종류 등). 여러 창이면 여러 장

## 3. 가이드라인 양식(복사해서 쓴다)

```markdown
# <주제> — 디자인 가이드라인
- 상태: 작성 중 | 구현 요청 | 구현됨(vYYMMDD-N, Claude)
- 대상 화면: docs/ui-screens.md <절 번호·표 이름> (예: 4.2 `profile`)
- 한 줄 요약: <무엇을 어떻게 — 예: 프로필 창 카드를 판자 질감 프레임으로, 선택 체크를 금박 도장으로>

## 바꿀 요소
| 요소 | 엔티티 이름(ui-screens 표 그대로) | 지금 | 바꾼 뒤(색 #RRGGBB·알파 / 크기 px / 위치 / 글꼴 크기·굵기) | 쓰는 이미지 |
|---|---|---|---|---|
| 카드 틀 | `RtsThemeCard{k}` | 단색 + 금 테두리 | 이미지 9-slice, 모서리 12px | profile-card-frame.png |

## 이미지
| 파일(assets/design/…) | 쓰임 | 크기(px) | 투명 | 늘려 쓰기(9-slice 모서리 px / 통째) |
|---|---|---|---|---|

## 상태별 모양(있으면)
- 선택 / 비선택 / 잠김 / 마우스 올림 / 누름 …

## 지켜야 할 것
- (아래 4절 공통 규칙 외에 이 주제만의 것)

## 참고 그림
- (스크린샷·시안 경로)
```

## 4. 공통 규칙(가이드라인이 이것과 부딪치면 Claude가 사용자에게 묻는다)
- 색·글자 크기·컴포넌트 상태는 `docs/design-system.md` 3·4절 토큰을 이름으로 가리켜도 된다(예: "주요 행동 색", "보조 글자")
- 화면 문구에 개발용 분류(티어·서포터·1티어 등) 금지. 문구를 바꾸면 가이드라인에 새 문구를 그대로 적는다
- 게임 규칙·밸런스·서버 동작은 바꾸지 않는다(보이는 것만). 프리셋 `key`, DataStorage 키, RPC 서명은 그대로(`docs/theme-presets.md` 5절)
- 해상도 기준 1920×1080, 좌표·크기는 px(ui-screens 표와 같은 단위). 글자는 칸보다 길면 자동으로 줄어든다(BestFit — 최소 60%)
- 화면이 바뀔 때 바뀐 칸만 다시 그린다(ui-screens 7.3) — 가이드라인은 모양만 정하고, 다시 그리는 방식은 Claude가 맞춘다
- 이미지는 PNG, 가능하면 필요한 크기의 1~2배. 스프라이트 업로드 기준 PPU 100(월드 스프라이트 1칸 = 80px 격자 기준은 ui-screens 5장·msw-engine 참고)
- 테마 썸네일 권장 400×240(5:3) — 쓰이는 곳: 프로필 카드 250×200 · 좌상단 상자 배경 400×240(프로필 + 정보 합친 상자) · 유저 카드 배경 250×150 (2026-09-25 — 뒤 둘은 5:3이라 늘리거나 자르지 않음)

## 5. Claude 쪽 처리 순서(참고)
1. `docs/design/`에서 상태 '구현 요청'인 가이드라인을 읽는다(모르는 점은 사용자에게 한 번에 묻는다)
2. 이미지 → msw-mcp로 **새 리소스** 업로드(기존 RUID 교체 금지 — Maker 캐시) → RUID를 코드 프로퍼티·프리셋 표에, `assets/textures/README.md` 또는 해당 문서에 기록
3. 코드는 Client `Build*`·`Apply*`·`Refresh*` 안에서만 바꾼다 → Maker 재시작 → 스크린샷으로 가이드라인과 대조
4. `docs/ui-screens.md` 표를 새 값으로, 가이드라인 상태를 '구현됨(버전)'으로 → 사용자 확인 뒤 커밋
