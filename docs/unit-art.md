현재 적용(2026-09-27): 팔라딘·다크나이트·나이트로드·섀도어·팬텀 전용 흉상 5종과 팬텀 대기 3장·조커 8장·별도 카드/고리를 게임에 연결했다. 팬텀 카드는 고리 가장자리가 캐릭터와 살짝 겹치도록 대상 방향 앞 1.55유닛, 높이 0.84에서 출발한다. 카드 1.152×1.728유닛·고리 2.528유닛 크기는 유지한다. 현재 11직업 모두 전용 PNG 외형·흉상 사용. 상세: docs/design/five-class-portraits-phantom.md.

# 유닛 원화·프레임 (캐릭터 스킨)

- 최신 공통 기준: **현재 비숍의 원화·대기·스킬 프레임·흉상 구성, 그림체와 인체비율**. 모든 직업은 같은 작화 방식과 신체 구조를 따르며, 각자의 승인된 외모·의상·색·무기·표정 컨셉은 보존한다. 생성할 때 [비숍 기준 공통 프롬프트](design/unit-art-prompts.md)를 사용하고 실제 기준 이미지를 첨부한다. 이전 썬콜 공통 기준과 비숍을 비율 참고로만 한정한 규칙은 대체한다. 기존 작업 이력: [인체비율 점검](design/character-proportions.md).

- 히어로: `docs/design/hero-motion.md` — 외형·대기·스킬·흉상 게임 연결 완료.
- 프레임 확장 현황: `docs/design/unit-motion.md`. 새 PNG와 현재 게임에 연결된 RUID를 구분한다.
- 후속 디자인용 확정 원화 7종: [캐릭터 원화 인계](design/character-concepts.md). 다크나이트는 비홀더를 제거한 마지막 결과다. [신궁](design/marksman-motion.md)은 비숍 엔젤레이 기준의 최종 프레임 업로드·게임 연결·Maker 실제 재생·사용자 승인을 완료했다. [보우마스터](design/bowmaster-motion.md)는 승인한 한쪽 무릎 수직 발사 자세를 포함해 대기·스킬·흉상의 게임 연결과 Maker 검증을 완료했다. [5종](design/five-class-motion.md)의 원화와 대기·공격 PNG 78장 중 [팔라딘·다크나이트 32장](design/paladin-dark-knight-motion.md)은 게임 연결·Maker 검증 완료. 나이트로드·섀도어도 적용 완료, 팬텀은 적용 전이다. 팔라딘·다크나이트의 전용 흉상은 미제작이며 대기 01을 임시 사용한다.

메월 아바타 대신 직접 그린 PNG로 유닛을 보여 주는 작업의 기준 문서다. 원화·프레임·흉상을 만들거나 바꿀 때 이 문서 하나를 따른다.
- 사용자 결정과 그 이유: `.beaver/memory/_archived/character-art.md` (문서로 반영 후 보관)
- 캐릭터별 적용 기록(RUID·재생 시간·검증): 썬콜 = `docs/design/ice-lightning-mage-motion.md`; 불·독 = `docs/design/fire-poison-mage-motion.md`; 비숍 = `docs/design/bishop-motion.md`.

## 1. 작업 순서

1. **컨셉·원화** — [공통 프롬프트](design/unit-art-prompts.md)의 비숍 기준 이미지를 실제로 열고 생성 도구에 첨부한다. 직업의 외모·색·의상·소품·**표정 컨셉**을 채워 원화 1장을 보여 준다. **사용자 OK 전에는 프레임을 만들지 않는다.** 이미 승인된 캐릭터를 고칠 때는 현재 결과물을 기준으로 필요한 부분만 고친다.
2. **프레임** — 대기는 작은 호흡·옷자락 변화가 이어지는 복수 프레임으로 만든다. 공격은 준비 · 시전 · 마무리 사이의 연결 자세를 그려 부드럽게 이어 준다(현재 원화 4종: 대기 3장, 마법사 스킬 5장, 히어로 일반기 8장·인레이지 7장). 시전이 끝나기 전에 대기로 돌아가지 않고 패시브에 공격 프레임을 늘리지 않는다. 기존 액션의 자세 순서·타격 시점을 따른다. 직업·스킬 목록은 `.info/character.md`·`.info/skill.md`.
3. **흉상** — `portrait.png` 512×512 투명. 얼굴·어깨·가슴 윗부분. 전투 프레임과 따로 만든다.
4. **검수** — 모든 프레임을 같은 표시 크기·발 기준점으로 나란히 놓고 2절 기준으로 본다.
5. **게임 적용**(요청이 있을 때) — 새 RUID로 업로드 → 4절 표에 연결 → Maker 확인(5절). 파일만 바꾸고 적용 완료라고 하지 않는다.
6. **설정 동기화** — 외형·모션·흉상 변경을 `.info/character.md`·`.info/motion.md`·`.info/skill.md`와 해당 적용 기록에 함께 반영한다. 기존 장비 설명·이전 파일 경로가 현재 외형처럼 남지 않았는지 확인한다.

## 2. 그림 기준

- **그림체·외형**: 현재 비숍 `concept.png`·`frames/wait`·`frames/angel-ray`·`portrait.png`의 선, 눈과 얼굴 표현, 명암·하이라이트·채색 밀도를 공통 기준으로 한다. 각 직업의 고유 얼굴 특징·머리색·표정 컨셉·의상·무기는 보존한다. 비숍의 베이지 머리·금빛 눈·성직자 복장을 다른 직업에 복사하는 뜻이 아니다. 원화·프레임·흉상은 모두 같은 작화와 동일 인물로 보여야 한다.
- **비율**: 현재 비숍 대기 `assets/design/characters/bishop/frames/wait/motion01.png`와 엔젤레이 `frames/angel-ray/motion01.png`~`motion05.png`가 기준(중립 선 자세 약 2.30등신). 현재 `concept.png`는 원화 구성·작화 기준이며, 세부 신체 비율은 게임 프레임과 대조한다. 반려된 과거 2등신 콘셉트를 다시 기준으로 쓰지 않는다. 대기 캔버스 576×576·발 가운데 (288,512) 기준 육안 근삿값(모자·머리카락 끝·무기·책 제외):

  | 구간 | 값 | 뜻 |
  |---|---|---|
  | 정수리 → 발바닥 | 약 338px (y 174→512) | 신장 |
  | 정수리 → 턱 | 약 147px | 신장의 43.5% = 약 2.30등신 |
  | 턱 → 의상 밑단 | 약 119px | 비숍 의상 길이; 해부학적 골반 위치가 아님 |
  | 의상 밑단 → 발바닥 | 약 72px | 비숍 의상에서 드러나는 다리 구간 |
  | 얼굴 피부 가로 | 약 104px | 동일 표시 배율 비교용; 얼굴형은 직업 원화 유지 |

- 비율이 이미 기준에 가까운 원화는 다시 그리지 않고 보존한다. 의상 밑단 길이를 모든 직업에 강제하지 않는다. 포즈의 굽힘·원근을 고려해 머리/몸통/팔다리의 관계를 비교한다.
- **제작 통과 조건**: 전량 생성 전에 대상 대기 한 자세를 비숍 대기와 같은 머리 배율·발 기준선으로 비교한다. 긴 다리·부츠·작은 얼굴은 수정하고 진행한다. 프롬프트에 경로만 적지 말고 실제 이미지 참조를 전달한다. [공통 프롬프트의 검수 항목](design/unit-art-prompts.md)을 원화·전체 프레임·흉상에 각각 적용한다.

- **일관성**: 머리 크기·얼굴형·눈 위치·몸통·팔다리 길이, 피부·눈·머리·옷 색, 의상·문양·장식·신발·무기·소품을 모든 프레임에서 같게. 바뀌는 건 자세와 허용된 표정뿐이다. 포즈에 따른 굽힘·원근은 괜찮지만 머리가 커지거나 팔다리가 늘어나면 고친다.
- **크기 맞춤**: 이미지 전체 크기가 아니라 얼굴 폭·정수리~발로 맞춘다(무기를 들면 전체 크기가 달라진다).
- **표정**: 직업마다 원화 단계에서 정한다. 썬콜 = 은은한 미소. 다른 직업은 미정(일괄 미소 금지).
- 원화 승인 뒤 사용자가 비율 수정을 요청하면 그 요청을 우선한다.
- **움직임**: 사용자의 최신 요청에 따라 작은 호흡을 그린 대기 프레임을 반복한다. 발 위치·얼굴 크기는 고정하고 머리카락·옷자락·상체만 미세하게 바꾼다. 몸 전체의 위치·회전·확대/축소나 크로스페이드로 프레임을 대신하지 않는다. 과거 정지 1장 규칙은 폐기한다.

## 3. 파일

```text
assets/design/characters/<character-id>/
  concept.png (사용자가 보관을 요청한 확정 원화)
  portrait.png
  frames/
    wait/motion01.png, motion02.png, motion03.png
    <english-skill-name>/motion01.png, motion02.png, ...
```

- 번호는 01부터 재생 순서. 스킬 폴더명은 실제 스킬명을 영어 소문자·하이픈으로 표기한다(썬콜: `chain-lightning`, `blizzard`).
- **결과물만 둔다** — 사용자가 보관을 요청한 확정 원화는 직업별 `concept.png` 한 장을 기준 파일로 둔다(2026-09-27 요청). 그 외 원화 사본·레퍼런스·프롬프트·반려 시안·미리보기·스크립트·README는 넣지 않는다. 고칠 때는 같은 파일을 교체한다(`v2`·`final` 같은 복제 금지). 작업 기록은 캐릭터 적용 기록 문서나 `.beaver/output`에.
- 폴더·문서 이름에 날짜 접두어를 붙이지 않는다.

## 4. 게임 연결 (히어로·썬콜·불독·비숍·신궁·보우마스터·팔라딘·다크나이트·나이트로드·섀도어)

신궁은 비숍 엔젤레이를 기준으로 최종 프레임을 교체하고 새 RUID 연결·Maker 실제 재생·사용자 승인을 완료했다. 세부 기준은 [신궁 모션](design/marksman-motion.md)을 따른다.

| 무엇 | 어디 |
|---|---|
| 적용 직업·액션 → 프레임 RUID 목록 | `RtsJobTableLogic.HasMageSkin(jobId)` · `GetMageSkinFrames(jobId)` |
| 프레임별 재생 시간 | `RtsJobTableLogic.GetMageSkinFrameDurations(jobId)` (직업별 장수·시간은 `docs/design/unit-motion.md`) |
| 흉상 | `RtsJobTableLogic.GetMagePortraitRUID(jobId)` → 상세정보 `RtsUnitPopupLogic.SpawnPreviewAt`(180×180) · 선택창 `RtsPopupLogic.BuildRecruitInfo`(140×140) |
| 월드 표시 | `RtsUnitComponent.SetupMageSkin` · `PlayMageAction` · `DrawMageSkin` (대기도 시계를 돌리고 시간표를 반복한다) |
| 시전·대기 복귀 | `RtsSkillFxLogic.PlayCast` · `ReturnStand` · `CheckLoops` (비숍 디바인 퍼니시먼트는 `PlayMageLoop`로 5장 반복, 매 공격마다 시계를 초기화하지 않음) |
| 기본 아바타 빼기 | `RtsUnitLogic.SpawnUnit` (`HasMageSkin(jobId)`이면 AvatarRenderer·CostumeManager를 붙이지 않는다) |

- 캔버스: 대기 576×576·발 (288,512), 기본 공격 704×704·발 (352,640). 다크나이트 스피어 버스터 승인본은 긴 창을 깊게 뻗기 위해 832×832·발 (416,768)을 사용한다. 픽셀당 로컬 0.002유닛 — 무기 때문에 캔버스가 커져도 캐릭터 배율은 같다.
- 업로드는 msw-mcp 두 단계(`assets/textures/README.md` 절차). 같은 RUID에 덮어쓰지 않고 **새 RUID**로 올려 표를 바꾼다(Maker 캐시).
- 다른 직업은 적용 직업·프레임·시간·흉상 표에 새 분기를 추가한다. 기존 직업의 표를 덮어쓰지 않는다.

## 5. 적용 확인 (Maker)

[검증 절차](testing.md)의 stop → refresh_workspace → save → play 순서로 띄운 뒤:

- 흉상 — 선택창·상세정보 크기

확인하지 못한 항목은 완료 보고에 그 범위를 적는다.
