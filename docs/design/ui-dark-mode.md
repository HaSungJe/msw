# UI 다크모드

- 상태: 코드 반영, Maker 재시작·저장 복원 검증 대기
- 대상: 우측 하단 라이트·다크 스위치, HUD, 난이도 선택, 증강, 영입, 캐릭터 상세, 몬스터·보스 정보, 확인창
- 사용자 결정: 현재 라이트모드를 기본으로 유지하고, 다크모드는 계정별 선택값을 서버에 저장하여 다음 접속에도 사용한다.

## 화면

기존 크기·배치·물결 이미지를 유지한다. 밝은 면을 짙은 남색으로, 본문을 밝은 회백색으로 바꾼다. 프로필과 좌상단 정보 상자의 불투명 규칙은 두 모드에서 같다. 월드 배경, 사용자 카드의 선택 테마, 캐릭터·스킬·능력치·등급 아이콘은 원색을 보존한다.

| 요소 | 라이트 | 다크 |
|---|---|---|
| 기본 면 | 기존 백색 물결 | 기본 RGB(.10,.125,.18), 기존 면의 색조를 약하게 반영 |
| 본문 | RGB(.20,.22,.30) | RGB(.92,.94,.98) |
| 보조 글자 | RGB(.42,.44,.52) | RGB(.68,.73,.82) |
| 강조 글자 | RGB(.43,.42,.62) | RGB(.79,.78,1) |
| 중립 테두리 | 기존 은색 | RGB(.31,.36,.47), 기존 alpha 유지 |
| 물결 | 흰색 alpha .75 | RGB(.45,.53,.72), alpha .10 |
| 선택·위험·성공 | 기존 색 | 테두리·표시의 의미 색 유지, 어두운 글자만 가독성 보정 |

일반 다크 패널의 alpha는 최소 .94, 원래 불투명 면은 1이다. 투명 입력 영역은 그대로 투명하다. 원본 라이트 색을 저장해 전환을 반복해도 색이 누적 변형되지 않는다.

## 설정 위치·상태

우측 아래 맨 아래에 라이트·다크 좌우 스위치를 배치한다. 배속과 같은 212×64 크기이며 오른쪽·아래 여백은 각각 16px이다. 왼쪽은 라이트, 오른쪽은 다크다. 저장 중에는 기존 선택을 유지하고 선택된 쪽에 `저장 중…`을 표시한다. 성공·실패는 기존 HUD 안내로 전달한다. 프로필의 화면 탭과 선택 카드는 제거했다.

1배속·2배속 스위치는 바로 위에 12px 간격으로 고정한다(오른쪽 16px, 아래 92px). 멀티플레이 배속 투표 인원은 그 위에 표시한다. 일시정지는 상단 다시하기 오른쪽 12px 간격으로 옮기며, 둘 다 200×48이다. P 키캡과 솔로·진행 중 표시 조건은 유지한다.

저장 실패 시 이전 모드를 유지한다. 읽기 실패는 값 없음과 구분하며 기본값으로 저장소를 덮어쓰지 않는다.

## 저장·갱신 계약

- 기존 `UserDataStorage(userId)`에 독립 키 `uiMode`를 추가한다. 허용값은 `light` / `dark`, 저장값이 없거나 유효하지 않으면 표시 기본값 `light`다. 기존 테마·아이콘·비석 키는 바꾸지 않는다.
- 입장 때 한 번 읽고, 설정이 실제 바뀔 때만 서버에서 비동기로 저장한다. `senderUserId`의 계정만 허용하며 읽기 완료, 유효한 선택값, 중복 저장 및 짧은 연속 요청을 검증한다.
- 저장 성공 뒤 `ReceiveUiMode`로 요청한 사용자에게만 전달한다. 다시하기에서는 설정을 초기화하지 않으며, 새 접속은 서버에서 읽는다.
- `RtsHudLogic.SetUiColor`가 엔티티와 라이트 원본 색을 등록한다. 모드 전환은 기존 렌더러의 색만 갱신하고 창·선택·스크롤을 재생성하지 않는다. 삭제된 엔티티 참조는 생성 배치와 모드 전환 시 정리한다.
- 신규 UI도 패널·라벨 도우미와 `SetUiColor`를 사용한다. 원색 이미지·테마 배경은 등록하지 않거나 `fixed` 역할을 사용한다. 능력치 RichText 갱신은 `SetUiText`를 사용한다.

## 검증 현황

- 정적 변경 검사 완료. 새 키가 없는 Maker 계정의 실제 저장소 조회: `code=0`, `value=nil` 확인.
- 사용자가 직접 동작 테스트를 진행하므로 이번 배치 변경 후 Maker를 조작하거나 재시작하지 않았다.
- 라이트 기본 표시, 모드 전환, 부분 갱신 유지, 저장 후 재접속 복원, 각 팝업 시각 확인은 아직 완료 판정하지 않았다.
- Maker 저장소와 출시 저장소는 엔진상 분리되어 있다. 출시 후 실제 계정의 왕복도 별도로 확인한다.
