# 유닛 대기·공격 프레임 확장

## 상태

사용자 요청: 히어로 인게임 적용, 모든 캐릭터의 대기·공격 연결 프레임 증가. 원화가 있는 썬콜·불독·비숍·히어로 4종을 우선 제작했다. 나머지 7직업은 기존 MSW 아바타를 사용하며 변경하지 않았다.

39개 새 PNG를 승인받아 계정 리소스 저장소에 등록하고 기존 27개와 합쳐 66개 결과물을 게임에 연결했다. 히어로는 기본 아바타를 생성하지 않고 전용 PNG·검 이펙트를 사용한다. 흉상도 공용 영입·상세정보 경로에 연결했다.

결과물은 `assets/design/characters/<id>/frames/wait/` 및 각 스킬 폴더의 `motion01.png`부터 재생 순서대로 관리한다. 원본 공격 3장은 01/03/05, 히어로 인레이지 4장은 01/03/05/07이며 사이에 연결 자세를 추가했다.

## 구현·검증

- `HasMageSkin`에 히어로 포함. 네 직업은 기본 AvatarRenderer가 없는 상태로 13개 액션을 실제 표시했다.
- Maker 관측: 네 직업 대기 각 3장, 마법사 공격 각 5장, 히어로 일반기 8장·인레이지 7장을 빠짐없이 재생. 시전 후 stand1 복귀와 좌우 반전을 확인했다. 기록: `.beaver/output/unit-motion/verification.json`.
- 히어로 원본 검 스프라이트 14장 로드, 손잡이 기준 배치·좌우 반전. 최신 수정에서 기존 월드 배율 2.0으로 복원(직전 0.72 대비 약 2.78배). 일반기와 인레이지의 피해량·쿨타임은 유지한다.
- 블리자드 템페스트는 2초 간격 시전, 각각 1.85초 검사에서 stand1. 기본형은 동일한 1.8초 프레임표를 사용하며 낙하 착지와 판정을 1.32초로 맞췄다.
- 도트 퍼니셔 수명 5초: 클라이언트 실제 구체가 4.8초에는 존재하고 5.2초에는 제거됨. 서버는 최초 생성 기준 만료 시각을 예약 타격과 재조준에 검사하고 재조준 클라이언트에 남은 시간만 전달한다.
- 빌드 오류 0, 기존 경고 8. 추가 수정 실행 로그 오류 0. 기록: `.beaver/output/unit-motion/updates-verification.json`.
- 모션 고정 타이머는 종료했고 서버 공격 루프 4개를 복구했다. 사용자가 직접 인게임 동작을 확인 중이다. 흉상의 두 팝업 화면은 사용자 조작과 겹쳐 별도 육안 검증을 완료하지 않았다.

## 화면 수정

증강 선택 3장의 아이콘·제목·효과 설명을 하나의 묶음으로 가로·세로 중앙에 배치한다. 좌상단 정보 카드의 타이머 위치는 유지하고 그 아래에 난이도를 표시한다. 라운드·스페셜·타이머·맵·난이도·메소·필드 모두 같은 18px 일반 굵기 글꼴을 사용한다. 상세 배치는 `docs/ui-screens.md`.

## 추가 반영·재생 확인

히어로 공격 프레임 8장의 개인 검 제거·새 RUID 연결, 도트 퍼니셔 만료 위치의 무피해 적중 폭발, 유닛 목록 위로 압축·번호 제거, 몬스터/보스 백색 물결 상태창, 보유 탭의 개별 미선택 증강 목록과 구매 전용 뽑기 탭을 반영했다.

- 추가 검증: 도트 퍼니셔 5.05초에 구체는 제거되고 같은 위치에 적중 클립이 생성되며 6.5초에는 폭발도 정리된다. 몬스터/보스 상태창은 실제 화면에서 확인했다.
- 미선택 7건 목록에서 골드 건을 열어 받기 버튼 이벤트를 실행한 결과 보유 1건·미지정 1건·미선택 6건으로 변경되고, 이어 유닛 4에 지정됐다. 오래된 수령 요청의 중복 지급은 차단됐다. 10건 상한·오래된 건 제거·후보 유지도 서버 실행으로 확인했다.
- 받기 무반응의 원인은 검증 중 일시정지 상태였다. 해제 후 수령을 확인했고, 정지 중 안내와 뽑기 화면 생성 중 갱신 보호를 추가했다.
- 최종 확인: 인레이지 7프레임 모두 일반 검 이펙트가 숨겨지는 것을 확인했고 사용자가 재생을 승인했다. 확인용 반복 재생과 데이터를 정리한 새 Play에서 일시정지 해제·미선택 0·보유 0, 빌드 오류 0(경고 10)·실행 오류 0을 확인했다.
