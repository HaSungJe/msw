# 모바일·PC 전체 화면 재배치 시안

상태: **사용자 승인 시안 기반 게임 코드 반영 / Maker 검증 / 실기기 확인 대기**. HTML은 시안이며, 실제 런타임 배치와 검증 범위는 아래 공통 런타임 절을 따른다. 게시 월드에는 아직 반영하지 않았다.

## 산출물

- 시안집: `assets/design/mobile-ui/index.html`
- 대표 이미지: 같은 폴더의 `pc-light.png`, `pc-dark.png`, `mobile-light.png`, `mobile-dark.png`
- 기존 `assets/design/`의 캐릭터 흉상·대기 프레임·테마·등급·능력치 아이콘을 상대 경로로 재사용한다. 독립 HTML만 다른 폴더로 옮기면 이미지 연결이 끊긴다.
- 상단에서 모바일/PC, 라이트/다크, 16:9·19.5:9·20:9·21:9를 전환한다. 왼쪽 목록·검색·이전/다음으로 모든 화면을 볼 수 있다.
- URL의 `device`, `theme`, `ratio`와 해시로 특정 시안을 다시 열 수 있다. 예: `?device=pc&theme=dark&ratio=16#unit`.

## 사용자 의도

PC는 산재한 정보와 버튼을 정리하고 아이콘·간격·정렬·선택 표시를 통일한다. 모바일은 갤럭시와 아이폰의 가로 화면을 공통 지원하며, 큰 터치 영역과 좌우 가장자리 조작을 제공한다. 갤럭시 노트20은 확인 대상 중 하나이며 전용 규격이 아니다. 라이트와 다크는 같은 기능·배치를 공유한다.

## PC·모바일 배치와 조작

- 왼쪽 위는 프로필·진행 정보, 인원 표시를 포함한 유저 목록이다. 설정 버튼은 제거했다. 왼쪽 아래는 다시하기/일시정지, 그 아래 배속이다.
- 오른쪽은 영입·증강·유닛이며 캐릭터 선택·이동 시 해당 조작 메뉴로 전환한다. 화면 모드는 오른쪽 맨 아래다.
- 중앙은16×13 전투판의 비율을 보존하여 확대한다. 트랙 형태·서버 좌표·전투 규칙은 유지한다.
- 팝업의 헤더·탭·확정 버튼은 고정하고 목록을 스크롤한다. 모바일 실기기 터치 크기·노치는 별도 확인한다. 세로 방향은 지원하지 않는다.
- HTML과 대표 PNG는 이전 상·하단 배치 시안 기록이다. 실제 게임 배치는 아래 공통 런타임 규격을 따른다.

## 공통 시각 규칙

| 요소 | 라이트 | 다크 |
|---|---|---|
| 주요 패널 | 진주빛 백색 `#FCFCFF` | 남청색 `#1B2235` |
| 카드 | `#F2F2F9` | `#242E44` |
| 본문 | `#34384E` | `#EEF0FA` |
| 보조 글자 | `#757C91` | `#A3ADC5` |
| 강조 | 라벤더 `#8866DC` | 라벤더 `#B197F7` |
| 경계 | `#D9D9EB` | `#3F4964` |

- 둥근 패널, 얇은 경계선, 절제된 물결·그라데이션. 프로필과 읽기 중심 팝업은 불투명으로 유지한다.
- 주요 행동은 강조색 채움, 일반 행동은 옅은 카드, 방출은 붉은 계열. 색만으로 의미를 구분하지 않고 이름·아이콘·선택 경계선을 함께 사용한다.
- 아이콘은 동일한 선 굵기와 둥근 형태를 사용한다. 영입=추가, 증강=보석, 유닛=인물, 설정=톱니, 레벨업=위 화살표, 이동=방향 화살표, 방출=휴지통.
- 증강은 기존 등급 문양 안에 능력치 아이콘을 합성한다. 프리즘은 시안에서 직업 흉상으로 구분하며, 구현 시 기존 전용 스킬 아이콘 매핑을 연결한다. 공통 번개 하나로 모든 프리즘을 표시하지 않는다.
- 유저 카드는 왼쪽 아이콘·오른쪽 정렬 닉네임·개인의 테마 배경. 내 카드는 테두리와 마름모 문양으로 구분한다. 액션 테마는 게임에서 카드 배경에도 재생해야 하며 HTML 시안은 정지 이미지다.

## 유지할 기능 계약

1. 영입 창을 새로 열 때마다 모험가가 기본이다. 5개 직업군은 빈 칸이 있어도 표시한다. 영입 카드에는 레벨을 넣지 않는다. 영입 상세의 직업 특성은 5축, 보유 캐릭터의 현재 능력치는 6축이다.
2. 미선택 증강은 보유 목록에 개별 행으로 표시한다. 받기 → 미지정 → 유닛 지정 흐름을 유지한다. 적용 숨기기가 미선택 증강을 숨기면 안 된다.
3. 뽑기는 구매 전용이다. 구매 후 보유 탭의 대기 건수만 갱신하고 뽑기 페이지를 유지한다. 탭 진입만으로 뽑기 소리를 재생하지 않는다.
4. 프로필 변경 확인창은 원래 목록 위에 겹친다. 취소·적용 시 원래 탭과 스크롤을 보존한다. 부분 선택 변경으로 팝업 전체를 재생성하지 않는다.
5. 레벨업 불가/최대 레벨은 명시적으로 비활성화하고 이유를 표시한다. 방출·다시하기 확인과 서버 권한 검증을 유지한다.
6. 저장은 기존 서버 `uiMode` 계약을 사용한다. 실제 저장 실패 시 이전 모드로 복구하고 안내한다. 시안은 계정에 저장하지 않는다.
7. 모바일/PC는 표시 배치만 다르다. 보유 상태·직업·스킬·증강·확률·가격의 원본은 기존 게임 표를 사용한다.

## HTML 시안의 검증 한계

- 직업별 액티브·패시브 설명은 현재 `RtsJobTableLogic.mlua`에서 가져온 검토 시점의 스냅샷이다. 나머지 수치·레벨·보유 건수는 배치 확인용 예시이며 밸런스 변경안이 아니다.
- HTML 버튼은 화면 이동과 가벼운 예시 상태만 바꾼다. 실제 전투, 구매, 획득, 서버 저장, 액션 테마 재생은 구현되어 있지 않다.
- HTML의 전체 렌더링 방식은 시안용이다. 게임 구현에서는 현재 부분 갱신 규칙을 따라 탭·스크롤·선택 상태를 보존해야 한다.
- 브라우저에서 모든 화면의 이미지 로드·가로 넘침·확인창 높이를 순회 점검하고, 주요 화면을 직접 시각 확인한다. 모바일 실기기 터치·노치는 별도 수행한다. Maker 런타임 결과는 아래에 구분한다.
- 구현 시 `docs/ui-screens.md`, `docs/msw-engine.md`, `docs/design-system.md`, `docs/design/ui-dark-mode.md`와 대조한다. HTML 예시 수치와 실제 런타임 수치를 혼동하지 않는다.

## PC·모바일 공통 런타임 배치

`RootDesk/MyDesk/UI/RtsUiLayoutLogic.mlua`가 기존 HUD 엔티티를 재배치한다. 서버 게임 규칙·가격·계정 저장 계약은 유지한다. 아래 좌우 배치는 상·하단 바를 사용했던 HTML 시안보다 우선하는 현재 구현이다.

- 가로 화면을 지원하며 실제 화면을 `ScreenToUIPosition`으로 측정하고 높이/1080 배율을 사용한다. 전투판·캐릭터는 종횡비를 유지하고 배경은 화면을 채운다.
- 높이1080 환산 여백은 PC 좌우28·상하24, 모바일 좌우32·상하20이다. 공개 SafeArea API를 이용한 값이 아니므로 실제 갤럭시·아이폰의 노치와 모서리 확인이 필요하다.
- 왼쪽 위: 프로필·진행 정보340×316 → 유저 목록340×88(현재 인원 표시, 상단330 위치). 왼쪽 맨 아래에는 배속1/2 버튼164×88, 그 위12 간격으로 다시하기/일시정지164×96을 나란히 둔다.
- 오른쪽: 플랫폼 메뉴를 피하여 상단에서140 내려온 위치에 영입·증강·유닛을 세로로 배치한다. 패널300×336, 버튼276×96, 간격12. 96 높이의 가로형이다. 라이트·다크 스위치는 오른쪽 맨 아래다. PC 보유 유닛 목록은 주 메뉴 아래440 높이 영역에300×116 카드·124 간격으로 페이지당3명을 표시한다. 흉상80, 직업명22·레벨20이며 하단 좌우 화살표와 현재/전체 페이지를 표시한다. 모바일의 유닛 창도 페이지당3명을 표시한다.
- 캐릭터 선택 시 오른쪽 메뉴가 뒤로·상세보기·레벨업·이동·방출로 바뀐다. 선택 영역의 표시 사각형과 월드 입력 차단 사각형을 함께 갱신한다. 배치/이동 안내와 취소도 오른쪽에 표시하고 중앙의 중복 안내를 숨긴다. PC의 S·스페이스·L·Esc 및 P 단축키는 유지하며 모바일에서는 키캡을 숨긴다.
- 영입 가능 조건을 만족하면 오른쪽 영입 버튼에 `영입 가능 n명`과 강조 배경·테두리를 유지한다. 영입·방출·라운드 변화 시 제자리 갱신한다.
- 보드는 좌측340+간격20, 우측300+간격20을 제외한 중앙을 쓰고 상하에는12만 더 남긴다. 예전 상·하단 조작 바 영역을 확보하여 트랙·캐릭터·이펙트를 같은 비율로 확대한다. 서버 보드는 identity이며 클라이언트만 균등 변환한다. 입력은 `ScreenToBoard`, 화면 투영은 `BoardToScreen`을 사용한다.
- 캐릭터 상세1360×780: 능력치·액티브·패시브·증강·버프5탭. 능력치 왼쪽 흉상/6축, 오른쪽 증가량·보스 DPS/효율. 다른 상세 탭은 전체 본문 폭을 사용하고 레벨업은 고정한다.
- 증강1360×880: 보유·뽑기·도감 탭88. 미선택 받기→미지정→지정 흐름을 유지한다. 보유 목록5행, 선택 카드3장, 지정 대상2명, 도감 최대3행을 페이지로 나눈다. 도감 설명을 펼치면 높이에 맞춰 페이지를 다시 계산한다. 선택 카드420×530의 아이콘y−48·제목y−172·설명y−244·받기88을 고정한다.
- 영입1320×760: 계열 탭88·5직업군·카드243.6×132. 상세1320×740. 열 때마다 모험가 선택, 레벨 없는 카드, 빈 직업군 표시를 유지한다.
- 프로필1320×780: 기본 탭76·종류 탭64, 테마/비석4열·아이콘8열. 확인창은 기존 목록 위에 겹친다. 유저 목록은2열×최대4행이며 개인 테마·아이콘·내 카드 표시를 재사용한다.
- 유저 목록/유닛 창960×650. 중복 설정 진입 버튼은 제거하고 프로필·배속·화면 모드는 HUD에서 바로 조작한다. 모바일 팝업은 화면 여백 안에 균등 맞춤(작은 창 최대1.5배), 닫기88. 확인·방출·결과 버튼88. 몬스터 정보는 기존 하단 중앙 위치를 유지하며 모바일 디버프 탭 설명과 PC 마우스 오버를 지원한다.

### 증강 글자와 정렬

증강 글자의 획일적24 확대는 취소했다. 이름22~24, 효과 설명20, 직업명·확률·보조 문구17~18 중심으로 구분하고 기존 굵기 차이를 유지한다. 글꼴은 다시하기와 같은 uitext다. 증강 셸은1360×880, 긴 선택 설명을 위해 카드 높이530·본문176을 사용한다. 보유 탭 하단의 개수/방출 안내 문구는 제거하며 상단 요약은 유지한다. 뽑기 등급4개 박스는 등급명·확률·안내 모두 가운데 정렬한다. 프리즘 도감은 아이콘 중심y−46에 직업명 박스·스킬명·자세히·확률의 세로 중심을 맞춘다.

### 페이지 조작

목록 아래 왼쪽·오른쪽 끝의 화살표와 `1/2` 형식의 현재/전체 페이지를 사용한다. 도감은 이전 스크롤바용 오른쪽16 여백을 제거하여 양쪽 버튼 여백을 맞춘다. 첫/마지막 페이지의 이동 불가 화살표는 흐리게 비활성화한다. 페이지 이동은 기존 엔티티 표시만 바꾸며 창·선택·스크롤이 아닌 페이지 상태를 보존한다. 수령·방출·필터 변경 후 총 페이지가 줄면 마지막 유효 페이지로 보정한다. 증강 선택 인덱스는 원래 후보 배열을 유지하고 넘기기만으로 뽑기 소리를 재생하지 않는다.
