# 메이플 증강 디펜스 — 디자인 기준과 구현 인계

> 2026-09-25 기준. 화면의 실제 동작·좌표·갱신 규칙은 `docs/ui-screens.md`, 테마 제작 경계는 `docs/theme-presets.md`, 엔진 제약은 `docs/msw-engine.md`를 우선한다. 이 문서는 시각 방향과 작업 순서를 정한다.

## 1. 디자인 방향

- **친근한 메이플 카툰**: 둥근 실루엣, 따뜻한 크림·코랄·금색, 밝은 초록과 하늘색. 선택된 홍보 이미지 `assets/thumbnail/thumbnail_16x9_soft_cartoon.png`와 `thumbnail_1x1_soft_cartoon.png`를 분위기 기준으로 삼는다.
- 홍보 이미지는 일러스트다. 실제 플레이 UI에는 그림을 크게 붙이지 않고, **맵 위에서도 읽히는 정보 위계**와 빠른 조작을 우선한다. 직업·몬스터·보스의 실제 외형은 원작/MSW 자산을 쓴다. 임의로 재해석한 캐릭터를 게임 화면에 섞지 않는다.
- 한 화면의 강조색은 한 번에 한 가지 행동에 집중한다. 금색은 지금 할 수 있는 주요 행동, 초록은 내 상태·완료, 코랄은 위험·탈락, 보라는 프리즘에 쓴다. 모든 테두리를 금색으로 칠하지 않는다.
- 공간 UI는 플레이 영역을 침범하지 않는다. 기존 큰 배치(좌상단 정보·유저, 우측 유닛, 좌하단 증강, 중앙 팝업)는 유지하고 카드 안의 위계와 간격부터 다듬는다.

## 2. 현재 구조와 디자인 소유 범위

| 영역 | 구현 위치 | 디자인 작업 |
|---|---|---|
| HUD 공통 생성기·색 | `RootDesk/MyDesk/RtsHudLogic.mlua` | 색 토큰, 패널·버튼·라벨·카드의 공통 모양 |
| 팝업 셸·영입·증강·도감·프로필·아이콘·결과 | `RtsPopupLogic.mlua` | 창 위계, 탭·목록·카드·확인창·결과창 |
| 유닛 상세·캐릭터 메뉴 | `RtsUnitPopupLogic.mlua`, `RtsUnitSelectLogic.mlua` | 외형판, 능력치, 스킬/증강 목록, 선택 상태 |
| 난이도·몬스터 정보 | `RtsDifficultyLogic.mlua`, `RtsMonsterInfoLogic.mlua` | 중요한 수치, 상태색, 툴팁 |
| 월드 테마·비석 | `RtsThemeLogic.mlua`, `RtsTombLogic.mlua`, `assets/textures/`, `tools/gen-*.js` | 바닥·트랙·장식·테마 썸네일·비석 아트. 프리셋 값의 경계는 `docs/theme-presets.md` |
| 홍보 이미지 | `assets/thumbnail/` | 16:9·1:1 및 용량 제한본 |

UI는 `.ui` 파일이 아니라 `model://uigroup`, `uisprite`, `uitext`, `uibutton` 등을 **클라이언트에서 런타임 생성**한다. 기준 좌표는 1920×1080이다. `RtsHudLogic.SpawnPanel`은 안쪽 패널을 반환한다. 기존 호출과 이 반환 약속은 유지한다.

## 3. 공통 시각 토큰

아래는 1차 목표값이다. MSW `Color`로 적용할 때 실제 플레이 캡처에서 한 번 조정한다. 기존 메서드 이름은 유지하고 반환값부터 바꾼다. `RtsPopupLogic.Base/Mix`와 직접 적힌 색도 함께 점검한다.

| 역할 | 목표 HEX | 적용 기준 |
|---|---|---|
| 기본 패널 | `#2D241E`, 불투명도 약 92% | 현재 거의 검정인 HUD에 따뜻함을 더하되 다양한 맵 위에서 읽히게 |
| 팝업 바탕 | `#352820`, 불투명도 약 97% | 본문보다 제목·선택 영역이 조금 밝게 보이도록 |
| 위에 얹는 카드 | `#49362B` | 선택지·상세·정보 구역에만 사용 |
| 기본 글자 | `#FFF1D8` | 제목·값·본문 |
| 보조 글자 | `#D4BEA2` | 설명·보조 수치. 배경과 구분 안 되는 회색은 피함 |
| 기본 테두리 | `#B99161`, 불투명도 약 65% | 일반 패널 |
| 약한 구분선 | `#A78562`, 불투명도 약 35% | 행·영역 사이 |
| 주요 행동 | `#F2C66D` | 영입·선택·확인·증강 카드 |
| 내 상태·완료 | `#78C58C` | 내 유저 카드, 적용 완료 |
| 정보·빙결 | `#7BBDE8` | 마법·정보 |
| 프리즘 | `#BD95E9` | 프리즘 등급에만 |
| 위험·탈락 | `#E67E73` | 필드 임계·방출·탈락 |

글자 크기는 **1920×1080 기준**이다. 창 제목 28~30, 영역 제목 21~23, 주 행동 18~20, 본문 16~18, 보조 14~15를 기본으로 한다. 실제 플레이 캡처가 1187×668로 축소되어 보이는 경우 12px 글자는 읽기 어렵다. 중요한 수치를 `BestFit`으로 9px까지 줄여 끼우지 말고 칸을 넓히거나 문구를 줄인다. 간격은 8px 단위, 패널 안 여백은 16~24px를 기준으로 한다.

## 4. 공통 컴포넌트 약속

Claude Code가 `RtsHudLogic`의 기존 `Spawn*` 헬퍼 위에 시각 상태를 얹는다. 한 번에 모든 호출처를 바꾸지 않고 새 스타일을 작은 화면에 적용한 뒤 확장한다.

| 컴포넌트 | 상태 | 시각 기준 |
|---|---|---|
| 패널 | 보통·강조 | 보통은 낮은 대비 테두리, 강조는 위에 얹는 카드색과 제목 띠. 내용 여백을 통일 |
| 행동 버튼 | 기본·주요·위험·비활성 | 채움색·글자색·테두리로 4상태를 명확히 구분. 클릭 영역은 기존 `SpawnClick` 사용 |
| 탭 | 선택·미선택·비활성 | 선택 탭만 채움과 굵은 글자. 전환 시 탭 엔티티는 유지하고 색만 바꿈 |
| 목록 행/카드 | 기본·선택·보유·미보유 | 선택은 배경과 얇은 강조선. 미보유는 흐림으로 표시하되 이름은 읽히게 |
| 상태 칩 | 성공·정보·프리즘·위험 | 작은 색 면적과 짧은 단어. 같은 뜻을 색만으로 구분하지 않음 |
| 팝업 셸 | 일반·결정 강제 | 제목, 본문, 하단 행동의 간격 통일. `pick`의 닫기 제한 유지 |
| 유저 카드 | 내 카드·관전·탈락 | 내 카드의 초록 테두리, 관전 금색, 탈락 감광을 유지. 배경 썸네일 위에 닉네임을 읽을 어두운 막 |

실제 메서드 이름·인자 수는 기존 코드와 충돌하지 않게 정한다. `SpawnPanel` 반환값, `SpawnClick` 효과음, `SpawnClickQuiet`의 예외, 팝업의 부분 갱신과 지연 제거(`DropLater`)를 그대로 지킨다. 새 헬퍼가 필요한 경우 **ClientOnly 시각 헬퍼**로 추가한다.

## 5. 화면별 디자인 우선순위

1. **테마 카드·유저 카드**: `docs/theme-presets.md`의 5개 프리셋 중 헤네시스 외 4개는 임시 바닥/트랙 틴트·썸네일 없음. 각 테마의 바닥·트랙·장식·400×240 썸네일을 한 세트로 만든다. 유저 카드 배경으로도 쓰이므로 중앙의 밝기와 닉네임 대비를 확인한다. `key`·경로·칸 수는 바꾸지 않는다.
2. **공통 토큰과 결과 창 시범 적용**: 실제 2026-09-25 플레이 캡처에서 결과 창은 내용이 좁은 왼쪽에 몰리고 패널 오른쪽이 비어 보인다. 결과 머리글, 도달/처치/개인 최고, 하단 행동을 분명한 세 구역으로 정리한다. 클리어/탈락 구분은 단어와 색을 같이 쓴다. 이 한 화면으로 글자 크기·대비·버튼 상태를 검증한 뒤 다른 창에 퍼뜨린다.
3. **판중 HUD**: 스테이지·남은 시간·필드 수를 우선 읽게 하고, 영입/증강 가능 여부를 주 행동으로 보인다. 프로필과 도감은 보조 행동이다. 우측 슬롯은 직업명·레벨이 축소 화면에서도 읽혀야 한다.
4. **결정 팝업**: 영입 상세, 증강 3택1, 증강 지정, 방출/다시하기 확인. 선택 결과와 취소/접기 경로를 명확히 구분한다.
5. **정보·수집 팝업**: 유닛 상세, 프로필/테마/비석, 아이콘 247종, 증강 도감, 몬스터 정보. 긴 목록은 현재 스크롤·배치 갱신 구조를 유지한다.
6. **추후 로비·순위**: 멀티와 순위표는 아직 구현 전이다. 지금 게임 안에 순위 버튼을 새로 넣지 않는다. 새 화면 설계 때 위 토큰을 재사용한다.

## 6. 아트 제작과 코드 적용의 분담

- **ChatGPT 담당**: 시각 방향, 테마별 아트 명세, 필요한 PNG 제작·검수, 화면 캡처 리뷰, 최종 시각 승인까지 반복. 이전 썸네일처럼 원작 보스 외형을 추측해 그리지 않고 공식 게임 자산이나 검증된 참고를 쓴다.
- **Claude Code 담당 가능**: 이 문서의 토큰·컴포넌트를 `ClientOnly` UI 코드에 적용, 위치/간격/글자 조정, 신규 이미지 업로드 후 RUID 연결, 각 화면 상태별 Play 검증, `docs/ui-screens.md` 갱신. 서버 로직·RPC·저장 키·트랙 경로는 디자인 작업에 포함하지 않는다.
- 이미지 파일은 프로젝트에 먼저 저장하고 새 리소스 RUID로 올린다. 기존 RUID 데이터 덮어쓰기는 Maker 캐시 때문에 피한다. 테마 프리셋 연결은 `docs/theme-presets.md` 절차를 따른다.
- 사용자에게 보이는 문구에 `1티어`, `2티어`, `서포터` 같은 개발 분류를 넣지 않는다.

## 7. Claude Code 첫 구현 작업 지시

`AGENT.md`, `.beaver/memory/`, `CLAUDE.md`, `docs/ui-screens.md`, `docs/theme-presets.md`, 이 문서 순으로 확인한다. 기능 단계는 로드맵의 **테마·아이콘 → 전체 UI 개선** 순서를 따른다. UI 개선 단계의 **첫 구현 범위는 디자인 토큰·공통 버튼/탭 스타일과 `result` 결과 창 한 화면**으로 제한한다. `RtsHudLogic`의 기존 시각 토큰과 `RtsPopupLogic`의 ClientOnly 결과 창만 고친다. 서버 메서드, RPC 서명, `SpawnPanel` 반환 약속, 팝업 열기/닫기·부분 갱신 구조, 보상/재시작 동작은 바꾸지 않는다. 결과 창을 클리어·필드 탈락·보스 시간 초과 각각 확인한다. 사용자가 플레이 중이면 화면 조작 없이 읽기 전용으로 점검하고, Play 재시작이 가능한 상황에서는 `maker_stop → maker_refresh_workspace → maker_save → maker_play → logs → screenshot`으로 확인한다. 축소된 화면에서 글자·버튼·대비를 본 뒤 `docs/ui-screens.md`의 해당 표를 갱신한다. **커밋·푸시는 사용자의 명시 승인 전까지 하지 않는다.** 이 시범 화면의 캡처와 변경 요약을 ChatGPT와 사용자에게 검토받은 다음 다음 화면으로 확장한다.
